# 前端视觉体系重构（Design System Refactor）

> 用户说「丑」「很丑」「所有页面依然是很丑」= **设计系统问题，不是组件问题**。
> 局部调整（加按钮/改布局/修对齐）解决不了——必须设计令牌级重构。
> 连续小修打不回时（"必须破而后立"）= **整体推倒重写**，别再打补丁。
> 实战来源：豆包配音工作台（2026-08-13~14），用户多次「很丑/很不满意/必须破而后立」反馈后验证有效。

## 触发条件

- 用户评价 UI「丑 / 很丑 / 不专业 / 不像产品」——尤其**「所有页面」级否定**
- 做过局部组件调整后用户仍不满意
- 评审发现：按钮样式多种混用、间距无规律、图标风格混杂、对比度不足
- **「必须破而后立」= 用户对增量修补的耐心已耗尽**，直接整体重写（见下）

## 诊断流程（先看像素，再下结论）

1. **真实截图**：capture_screenshot 保存全页截图。
   ⚠️ 不要只信 browser_vision 的文本描述——视觉模型会误读深色 UI（暗色气泡被说成"白色浅色模式"），判断必须以真实截图 + DOM 实测为准。
2. **vision_analyze 专业诊断**：加载截图，问「以专业 UI 设计师眼光逐项诊断：整体品质、配色/对比度、字体、按钮、卡片、间距、对齐、图标、与 Linear/Notion 的差距、最刺眼三处」。
3. 修完**再截图对比验证**：问「对比重构前是否明显变专业、按钮/输入/卡片风格统一了吗、接近 Linear/Notion 了吗」。

## 破而后立（小修打不回时的终局手段）

**触发信号**：连续 2+ 轮「真修+真验证（DOM 实测/vision 复评都过）」后用户仍说「不满意/很丑」——不是修得不对，是**结构本身不成立**。此时：
- 停止一切增量 patch（每轮修补都在浪费用户耐心）
- 直接声明「整体推倒重写，不再增量修补」，重写 HTML 骨架 + CSS 全块 + 相关 JS

**做法（以 AI 助手面板 2026-08-14 实战为例）**：
1. **重写 HTML 结构**（不复用旧 class 名，新命名空间如 `.ai-head/.ai-ctxbar/.ai-body`）——新结构天然消除旧债
2. **组件系统一次到位**：紧凑单行头部（图标+标题+状态徽章+操作按钮+关闭）、上下文 pill 条（`.ai-ctxbar`：项目名+关键数字 pill）、主区+右侧快捷能力栏、输入区+快捷键提示
3. **消息系统**：`renderMd()` 轻量 markdown 渲染器 + 气泡规范（见下）
4. **文案同步重写**：去技术黑话（"已连接 Hermes"→"服务正常"）、欢迎语结构化（能力列表）
5. **验证**：vision 复评必须出现「档次感明显提升/专业工具/组件统一」级结论才算过——只过功能测试不算

**判断工具**：vision 评估词区分「修补可回」vs「必须重写」——说「功能可用但体验粗糙/像技术 Demo/缺少质感投入」= 重写；说「个别细节问题」= 修补即可。

### 消息/聊天面板组件规范（重写时直接套）

- **气泡**：助手 `4px 14px 14px 14px` 圆角 + `surface3` 底 + 细边框 + `0 2px 10px` 微阴影；用户白底 `14px 14px 4px 14px` 右对齐；时间戳独立小字行（`font-size:.56rem; color:var(--faint); opacity:.65`）；`max-width:88%`（用户）/100%（助手）
- **markdown 渲染安全模式**：`renderMd()` 先 `esc()` 全量转义，再按序处理标记（``` 代码块 → 行内 `code` → `**加粗**` → `*斜体*` → `- ·` 列表 → `---` 分隔线），换行 `<br>`——注入内容已被转义成实体，无 XSS
- **上下文条**：项目名（ellipsis max-width）+ `ctx-pill`（边框胶囊小数字）实时刷新（打开面板时更新，不能静态）
- **输入区**：textarea 显式 `height:44px;min-height:44px;max-height:100px`（防 stretch，见根因 9）+ 容器 `align-items:flex-end`；发送按钮贴底
- **面板内部滚动容器单独定义细滚动条**（`::-webkit-scrollbar{width:6px}` + thumb `.18` hover `.3`），不吃全局 10px

## 常见根因清单（按出现频率）

### 1. :root CSS 变量自引用（致命，排查第一）
```css
--err-border: var(--err-border);  /* 循环引用 → 浏览器视为无效值 → 状态色全失效 */
```
- 现象：错误/成功/强调色边框"没生效"，代码里却有定义——悄悄全废
- 排查：grep 定义行里 `var(--xxx)` 出现在 `--xxx:` 右侧
- 高发场景：把 rgba 硬编码批量收敛为语义变量时手滑写成自引用

### 2. 胶囊按钮滥用（999px = "土"的根源）
- 现代工具（Linear/Notion/Stripe）按钮/输入/卡片统一 **6-8px 小圆角**
- 胶囊 999px 只该留给：进度条、状态标签 badge/tag、toast、滚动条、滑块轨道
- 排查：`grep border-radius:999px`，合理场景外全改 `var(--r)`/`var(--r-sm)`

### 3. 暗色主题对比度不足
- 次要文字 muted 透明度 ≥ .65、弱提示 faint ≥ .4（实战：.62→.68、.34→.42 显著改善）
- 灰字融背景 = 用户感知"脏"

### 4. 多套组件样式并存
- 同一页 2-3 套按钮（白底填充/灰底/透明胶囊）→ 观感混乱
- 修法：**两档按钮制**——主按钮（白底黑字，唯一重色）+ 次按钮（surface2 底+边框+hover 提亮），全站一套

### 5. 图标风格混杂
- 填充 vs 线条混用、stroke-width 2 与 1.5 并存 → 统一线条风格（1.5）

### 6. 间距无体系
- 无间距令牌 → padding/margin 随意 → "有的空有的挤"
- 修法：`--sp-1:4px; --sp-2:8px; --sp-3:12px; --sp-4:16px; --sp-5:24px` 逐步替换

### 7. 信息参数纵向摞成单列（用户两次因「纵向摞」喊丑）
- 现象：「参数还是很丑，全是纵向摞起来的」——详情/属性面板的「标签+值」列表一行一个字段，10 项占 10 行
- 修法：**任何「标签+值」列表信息默认网格卡片排布**（`.detail-params{display:grid;grid-template-columns:repeat(auto-fill,minmax(170px,1fr))}` + 标题 `grid-column:1/-1`），禁止单列纵向摞——实测 10 参数 3 列 4 行，「简洁专业」
- 配套：超长标识符（LOGID 类）`ellipsis` 单行 + `title` 悬停，grid 项 `min-width:0`；空值显 `—` 与真实 0 区分

### 8. 功能面板纵向堆叠（头部/状态/消息/输入一摞 = 「蠢分栏」）
- 用户参考 RunningHub 否定了「纵向一摞」的助手/聊天面板：改成**主区 + 右侧栏**（`.ai-main` flex:1 + `.ai-side` ~138px：快捷能力 chips + 实时上下文摘要，border-left 分隔 + surface2 底）
- **任何功能面板默认主区+侧栏，禁止全纵向堆叠**；侧栏数据打开时实时刷新（不能静态）
- 浮窗/窄面板内部滚动容器必须单独定义细滚动条（6px），别吃全局 10px 宽度

### 9. flex stretch 拉伸输入框（布局异常「左下角没用/大片空白」的真凶）
- 现象：输入框（textarea）莫名超高（260px），面板下部大片空白，甚至内容被裁掉
- 根因：`textarea{flex:1}` + flex 容器默认 `align-items:stretch` → 高度被拉伸到容器高度
- 修法：textarea 显式 `height:44px;min-height:44px;max-height:100px` + 容器 `align-items:flex-end`
- **通用排查法**：布局异常直接 `getBoundingClientRect` 打印布局树各元素 y/h（一眼定位谁撑爆），别靠猜

## 重构顺序（令牌 → 组件 → 图标 → 对齐）

1. **设计令牌**（:root 一次改完全局生效）：圆角（8/6/12px）、对比度（muted/faint）、间距令牌、状态色修正（先查自引用）
2. **组件体系**：按钮两档制 + 输入/卡片统一圆角 + hover 反馈（background 提亮 + transition）
3. **图标统一**：SVG stroke-width 统一
4. **对齐/细节**：view-head 对齐、信息密度、留白呼吸感

## 用户偏好锚点（本工作区）

- 暗色 Linear 风格（#08090a 底色），**白底按钮做唯一重色**
- 高密度、宽屏双栏、参数常显；宁密勿空，反感过度设计
- 4K + Windows 缩放下 CSS 媒体查询失效 → JS 测物理分辨率 + scale 变量补偿
- Hermes 桌面有预览面板（open_preview）时，改前端边改边看，效率高于反复截图
