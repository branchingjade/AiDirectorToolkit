# 知识库文档合成（从存量资产合成新文档）

> 适用：从已有知识资产（导演卡片/技法卡片/调研存档/项目文档）合成新的知识库文档（学科密码/题材密码/知识条目/专题综述），典型约束是"零新抓取、全部从存量合成"。
> 触发：接到"从存量资产写 X 文档"类任务时加载。

## 工作流

1. **模板先行**：动笔前先读目标目录的规范文件（00-模板规范/格式规范）——结构节、引用约定、质量纪律全在那里。不读模板直接写 = 返工。
2. **清点 + 测体量**：`search_files` 列出所有素材文件，`wc -c` 测大小。总素材常为产出的 10–20 倍（实测 400KB 素材 → 21KB 产出），先知道总量才能决定阅读策略。
3. **定向提取而非全文阅读**：30–55KB 的深度文档用 `grep -n "关键词"` 拿命中行号 + 上下文，再 `sed -n` 精读命中区；先 `grep -n "^#\|^##\|^###"` 拿目录结构判断素材里有什么。只有 <20KB 的小文件才全文读。全文硬读 400KB 会烧爆上下文且大部分无关。
4. **引用规范对齐模板**：模板定义缩写约定（如 [深·导演]=深化文档 / [卡·片名#N]=技法卡片第N张 / [招式·X]=招式表 / [检索·行名]=检索表），全文统一用缩写，来源清单里展开。每条论断带出处，没读到的段落宁可不引。
5. **用户决策必须取证**：任务简报声称的"用户拍板"要 grep 项目文档证实（版本记录/复盘文档里的"拍板/决定"字样），再标注【用户决策】；找不到就标注未取证，不默认成立。
6. **体量控制（关键）**：超目标时**不要整篇重写压缩**——LLM 会无意识恢复已删内容，整篇重写 4 次体量几乎不变（实测 26.9KB→22.5KB 反复横跳）。正确做法：
   - ① 用脚本按标题切分统计每节字节数（`re.split(r'(?m)^(## .*)$')`），找出最大开销节；
   - ② 对最大节做定点 patch 删除/压缩（删长引文、EN 提示词压缩为单行、表格去重复行）；
   - ③ 与同目录兄弟文档校准——并行批次产出的其他文档是真实体量基准。
7. **收尾验证**：`grep -c "^## "` 核对结构节数齐全（=模板要求节数）、grep 统计引用标注数量、确认无占位残留，再交差。

## 常见坑

1. **整篇重写压体量**：无效。分节字节统计 + 定点 patch 才是正解（见工作流 6）。
2. **素材章节名对不上**：任务简报说的章节（如"物件时代矩阵"）在素材里可能没有同名章节——grep 全库找最近似内容，引用后如实标注"以最接近内容为依据"，不虚构章节存在。
3. **引用只写不核**：引用编号必须对应真实读过的段落；偷懒编编号会在知识库扩散错误。
4. **体量目标脱离实际**："约 X KB"目标可能与同目录既有文档不符——以同目录兄弟文档大小为准校准（实测批次文档 18.5–23.2KB，而任务目标写 12–18KB）。校准后如实向派发方说明偏差。

## 验证

- 结构节数 = 模板要求节数
- 引用标注数 ≥ 预期（每节至少一条来源）
- 文件大小落在同目录文档区间内
- 【用户决策】类标注有项目文档实证
