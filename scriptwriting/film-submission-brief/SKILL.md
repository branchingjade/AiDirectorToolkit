# 影视项目送审材料撰写

> 立项申报/送审阶段，把已经成型的剧本改写成广电审批所需的四件套正文。**与"剧本创作"正交**——剧本是艺术创作，申报材料是按规范填表，二者不互相污染。

## 何时触发

- 用户说「广电送审」「立项申报」「电影局送审」「申报材料」「需要梗概/小传/内涵/阐述」
- 用户给的是**已成型的剧本**（飞书 docx 或本地文件），要求从中提炼出**故事梗概+人物小传+思想内涵+创作阐述**
- 一般出现在剧本题材完成、内审通过后、正式送审前

## 何时不触发

- 用户还在改剧本——送审材料以"已锁定的剧本正本"为准，剧本还在动就别写送审稿
- 用户给的是大纲/分场分析/概念——不是成品剧本，需要先回到编剧流程
- 用户给的是已写好的送审稿要润色——走 `feishu-comment-creative` 路径，不在此 skill 范围

## 工作流（Code-Act Loop）

### 1. 锁定剧本正本（必做，铁律）

- **优先以用户给的飞书 token/URL 为准**——这是送审稿的取材权威源
- MEMORY/Obsidian 里的"剧本"目录、`_知识库/伏妖记.md`、`AI电影编剧/AI电影导演` skill 的 project notes 都可能是**已淘汰旧副本**，不能作为送审稿直接引用
- 用户原话提到「你只需要看我给你说的那个文档」= MEMORY/项目知识库里的副本已被替代，必须用用户当前给的 token
- 用 `lark-cli docs +fetch --doc <token> --scope full` 拉全文，正本确认后再动笔

### 2. 四件套字数与体例（广电申报固定规格）

| 材料 | 字数区间 | 关键要求 |
|---|---|---|
| **故事梗概** | 1500-2000 字（按汉字数核验） | 全片故事完整讲述，**含起承转合/人物弧线/关键情节点**，不剧透结局反转 |
| **人物小传** | 不限（紧凑） | 主角+核心配角，每人 100-200 字，覆盖**外形/性格/功能/弧线** |
| **思想内涵** | 350 字左右（±10% 合格） | 主题/价值导向/社会意义，**不要说教**，落到具体意象 |
| **创作阐述** | 800-1200 字 | 题材定位/改编缘起/人物与主题/视听风格/节奏曲线/核心意象/文化指向，**不少于 5 个角度** |

字数口径：**汉字数 = 实际汉字字符数**（不含标点）。`doc_word_stat.py` 脚本的 `word_count` 字段可作为核对依据，但脚本口径是"语义单位"含中文标点——**送审稿目标按"汉字"核验，必要时手动 `re.findall(r'[\u4e00-\u9fff]', s)` 单独统计汉字数**。

### 3. 取材纪律（4 条铁律）

1. **只写剧本正文里有的事**——剧本未提及的设定（背景/关系/动机/身份）一律不补；用户原话「很多都是信息是故意藏着的」= MEMORY/Obsidian 里"待补全"的设定是创作者保留的信息密度，润色/送审稿都不要擅自补
2. **改编项目以用户给的最新正本为准**——`MEMORY`/项目文档/旧副本若与正本冲突，全部以正本为准；正本没写的设定不要补
3. **不剧透反转**——广电申报的故事梗概要在保留悬念的前提下完整讲完主线（参考：可以用「从A到B，最后C」结构，但C的内在机制不必写穿）
4. **不替创作者重新设定**——剧本里有留白/矛盾/未明确的留档，不要替创作者圆

### 4. 写作格式纪律

- **正式提交物 → 默认不用 callout/分栏/颜色/画板**——lark-doc-style.md 第23 行已有规定：「公文/法律/学术/申报/项目方案等严肃正式提交物默认不用高亮块、分栏」
- **走国人的艺术（国风/志怪/武侠项目专用）**：送审稿不用"三幕/建置/对抗/节拍/弧光"等西方术语，改用起承转合/拍/一波三折/信息一层一层揭开
- **数字优先用阿拉伯**：年份/时长/集数等一律阿拉伯数字
- **段落优先**，不用无意义的列表

### 5. 落盘到飞书（默认 `--as user`）

- 长材料（故事梗概 1500-2000 字）一次性写入足够（XML `<p>` 单段最大 2000 汉字内不会截断）
- **XML 先写到本地**（避免 shell 转义踩坑）→ `write_file` 落 `*.xml` → `lark-cli docs +create --as user --content @file.xml --title "..."`
- 一次性 `+create` 一份完整四件套文档（推荐结构：`<h1>一、故事梗概</h1><p>...</p><h1>二、人物小传</h1><h2>角色名</h2><p>...</p>...`）
- 创建后用 `docs +fetch --doc <new_url> --doc-format xml --detail full | doc_word_stat.py` 核字数（按 `lark-doc-word-stat.md` 流程）
- **每节字数单独 grep** 验证达标（脚本只统计总字数，分节字数要按 marker 切片自己跑）

### 6. 自检清单（提交前必跑）

- [ ] 故事梗概：起承转合完整？核心人物弧线讲到了？反转未穿？
- [ ] 人物小传：主角+核心配角全覆盖？每人覆盖外形/性格/功能/弧线？
- [ ] 思想内涵：350 字左右？不说教？有具体意象收束？
- [ ] 创作阐述：5+ 个角度？视听风格有具体细节（非空话）？
- [ ] 字数核验：汉字数 vs 目标区间达标？
- [ ] 取材核验：所有事实来自剧本正本，无 MEMORY/项目文档/旧副本带入？
- [ ] 体例核验：无 callout/分栏/颜色/画板（正式提交物）？
- [ ] 术语核验：国风项目无"三幕/建置/对抗/节拍/弧光"？

## 输出模板骨架

```xml
<title>《XX》广电送审材料（梗概·小传·内涵·阐述）</title>

<h1>一、故事梗概</h1>
<p>[1500-2000 字，从剧本开场讲到结尾，保留悬念不剧透反转；按"建置→发展→高潮→收束"四段，每段 350-500 字；主角弧线贯穿]</p>

<h1>二、人物小传</h1>
<h2>主角名</h2>
<p>[100-200 字：外形/年龄/性格/职业/功能/弧线起点→终点]</p>
<h2>核心配角 A</h2>
<p>[同上]</p>
...

<h1>三、思想内涵（约 350 字）</h1>
<p>[主题/价值/社会意义；不说教；以一个具体意象收束；350 字左右]</p>

<h1>四、创作阐述</h1>
<p><b>一、题材定位与改编缘起。</b>[为什么拍这个题材/改编自什么/目标受众/类型定位]</p>
<p><b>二、人物设置与主题表达。</b>[主角/反派/核心配角的功能 + 主题如何在人物身上具体化]</p>
<p><b>三、视听风格与影像呈现。</b>[色彩/光线/构图/镜头/剪辑/声音——每项至少一个具体决策]</p>
<p><b>四、叙事节奏与情感曲线。</b>[四段节奏+情绪曲线+段落时长]</p>
<p><b>五、核心意象与文化指向。</b>[3-5 个核心意象逐一拆解 + 文化传承/时代共鸣点]</p>
```

## 常见坑

1. **取材权威错位**——用 MEMORY/项目文档/Obsidian 旧副本当剧本，写出"剧本里没有的设定"。**第一刀必须 `lark-cli docs +fetch --scope full` 拉用户给的正本**，所有事实都要在正本里能找到
2. **补未提及设定**——剧本留白/信息密度被故意藏的设定，不要在送审稿里"补完"或"推断"
3. **剧透反转**——故事梗概里把核心反转机制讲穿了（典型：把幻境最后一层讲穿、把身世真相讲穿）
4. **字数按含标点核**——送审稿按"汉字数"核，含标点会虚高 10-20%
5. **混入西方结构术语**——国风/志怪/武侠项目送审稿出现"三幕/建置/对抗/节拍/弧光"
6. **用 callout/分栏/颜色**——正式提交物这些组件在外发/打印版会丢样式
7. **一句话人物小传**——只写"主角是一个伏妖师"——必须覆盖外形/性格/功能/弧线四要素
8. **创作阐述空话**——"视听风格独特、画面精美"——必须有具体决策（"色彩从青碧推向金红""符、剑、妖力三者合一"）

## 与相关 skill 的边界

- **`feishu-comment-creative`**：评论 agent 创作型任务的创作润色（对白打磨/优化台词），与送审材料四件套不同
- **`lark-doc`**：飞书文档读写的通用工作流——本 skill 在其之上聚焦"送审体例"
- **`yaoyu-film-knowledge-base`**：提供美学与制作招式（写作送审稿的"创作阐述"时按需取用）
- **`AI电影编剧`**：剧本正本的生产侧——送审稿素材来源；创作阐述的"视听/节奏/意象"维度可与其产物对齐
- **`AI电影导演`**：分镜/画面/节奏的导演侧——送审稿的"创作阐述"视听风格段可借其手法库
