# 剧本库建设与质量审计（screenplay-archive）

## 触发条件

- 用户要求"建剧本库/入库/完善剧本库"
- 抓取了一批剧本原文需要归档（film-suite-research → Obsidian）
- 用户反馈"剧本不完整/不规范/和原本不一样/来源引用不全"——这是质量审计没做，按本 skill 全量补

## 铁律：入库 ≠ 复制文件

**抓到的文本不是"剧本原文"，是"待审计的原料"**。直接复制进库 = 把杂质、版本差异、缺失来源一起带进去。用户（影视从业者）要求文献级标准：每份剧本必须能当参考资料用。

## 完整流程（六步）

### 1. 抓取（渠道分级）

| 渠道 | 用途 | 注意 |
|---|---|---|
| IMSDb / Script Slug | 英文原版主流 | IMSDb 常为流传稿，版本需核对 |
| juben.pro《剧本名作》 | 华语剧本全文（稀缺） | 实测有《饮食男女》151场、《新龙门客栈》175场、《小山回家》全文——华语作者电影剧本全网仅此渠道最全 |
| The Scripts Avant | 黑泽明/怀尔德等难找片 | 直链 PDF |
| The Successful Screenwriter | 黑泽明连续剧本 | 从成片反推，非编剧原稿 |

### 2. 清理杂质（每份必查）

- 网页 JS 残留（`if (window!= top)` 一类）——正则清除，注意空格变体（`window!= top` 与 `window != top` 都试）
- 分页符（`===== 第N页 =====`、PDF `\f`）——全量清理（`\f` 用 `content.replace("\f", "\n")`）
- PDF 装饰残留行——pdftotext 常见：纯符号行（`--- .·.`、`\.`、`^ --`、`·` 居中装饰线、`~~.`、`............ ?`）。正则：匹配纯符号行且不是合法分隔符（`---`/`***`/`___`/`...`）则删。注意 `***` 是剧本合法场景分隔，保留
- 控制字符——Tab（IMSDb 页脚 `\tForrest Gump`）、`\r`，统一清理
- OCR/编码乱码标题（如"F AR G0"→"FARGO"）——修复或标注
- 重复文件（同源不同名）——删一留一

### 2.5 编码检测（入库前必做，最容易漏）

**陷阱**：pdftotext / IMSDb 抓取的英文剧本常是 **cp1252 编码**，用 utf-8 + errors=replace 转换会产生大量 `�` 乱码（实测：断背山 604 处、血色将至 89 处）。看似能打开，其实内容已坏。

**铁律**：转换前先检测原始字节的真实编码——分别用 utf-8 和 cp1252 解码并统计 `\ufffd` 数量，谁少用谁：

```python
raw = open(src, "rb").read()
n_utf8 = raw.decode("utf-8", errors="replace").count("\ufffd")
n_cp   = raw.decode("cp1252", errors="replace").count("\ufffd")
enc = "utf-8" if n_utf8 == 0 else "cp1252" if n_cp < n_utf8 else "?"
```

- cp1252 源 → `raw.decode("cp1252")` 再写文件（保留 frontmatter）
- 转换后全库复检：每个 .md 统计 `\ufffd`，>0 即有问题
- **研习报告/卡片也查**（子代理输出的文件同样可能带坏字节，实测七武士研习报告 1 处 `Sak�`→`Saké`）

### 3. 元数据头（每份必带，YAML frontmatter）

**不要加 `# 文件名` 标题**——Obsidian 用文件名当标题，再加 H1 会和正文里剧本自己的标题（`MEMENTO - Shooting Script`）形成"两个标题"（用户实测纠正）。**不要用 `>` 引用块**——Obsidian 渲染出蓝色竖线，排版突兀（用户实测纠正）。用 YAML frontmatter：

```yaml
---
来源: "IMSDb（imsdb.com/scripts/Fargo.html）"
版本: "科恩兄弟流传稿"
与成片差异: "与上映版基本一致（自编自导）"
可信度: "🟢 流传稿≈拍摄稿"
抓取日期: "2026-08-06"
研习报告: "[[研习报告/冰血暴_研习报告]]"
---
FARGO
Original screenplay by
Joel Coen and Ethan Coen    ← 正文从剧本原标题直接开始
```

- frontmatter 字段：来源（渠道+URL）/版本（类型+日期）/与成片差异/可信度/抓取日期/研习报告（wikilink）
- frontmatter 后紧跟正文，**不要残留第二个 `---` 分隔线**（frontmatter 结束符已带 `---`）
- 研习报告链接：英文文件名剧本（如 brokeback_mountain_2005）需**显式映射**到中文报告名（断背山_研习报告），不能用 `[[研习报告/]]` 空链接

### 4. 版本可信度分级（写入 MOC）

| 级别 | 含义 | 示例 |
|---|---|---|
| 🟢 原稿/拍摄稿 | 编剧原稿或接近成片的拍摄稿 | 木兰花/闪灵/记忆碎片/血色将至 |
| 🟡 流传稿/译稿 | 流传稿或署名译者译本，与成片有出入 | 七武士英译/断背山/老无所依 |
| 🟠 早期稿/整理稿 | 与成片差异大，或非原稿的整理稿 | 七宗罪1992早期稿（无盒子反转）/新龙门客栈网版/饮食男女整理稿 |
| 🔴 反推稿 | 从成片逐镜头记录 | 罗生门连续剧本 |
| 📄 原著对照 | 非剧本，为改编来源 | 芥川竹林中 |

**使用铁律**：🟠 级别不可直接当拍摄稿引用；引用台词前先看文件头"与成片差异"。

### 4.5 华语/海外双区分库（用户要求）

**用户铁律（2026-08-06 明确要求）**："国内的剧本和国外的本子要分开"。库结构：

```
剧本库/
├─ 剧本库MOC.md
├─ 华语剧本/   ← 国内标准格式（第N场 地点 时间 内外）
│  ├─ 剧本原文/ + 研习报告/
└─ 海外剧本/   ← INT./EXT. 格式
   ├─ 剧本原文/ + 研习报告/
```

**分类规则：按剧本内容语言分，不是按片源地域**——中文格式归华语（含日片中文译稿如《摄影机不要停》、婚姻故事中文译本），英文归海外。研习报告同步分到对应区。分库后 MOC 里的 wikilink 路径要跟着改（`[[研习报告/X]]` → `[[华语剧本/研习报告/X]]`）。

**MOC wikilink 转义陷阱**：在 Python 里写 `\|` 会被转义成 `\\|`（双反斜杠），Obsidian 链接就断了（校验时路径末尾出现 `\`）。**用不转义的纯链接 `[[路径/文件名.md]]` 最稳**，不要在表格里写带别名的链接（`|` 别名在表格+Python 双重转义下极易出问题，实测全库 64 个链接断 20 个）。链接换行污染也会让 `[[` 和 `]]` 跨行——生成后必须校验"每个 `[[` 所在行含 `]]`"。

### 5. Obsidian 建库（关键陷阱）

- **Obsidian 默认只索引 .md，不显示 .txt**——剧本必须转 .md 才可见（用户实测：入库后"剧本正文没看到"= 没转 .md）
- 转换：txt → md，**顶部放 YAML frontmatter，不加 `#` 标题**（见第 3 步）；先做编码检测（见 2.5）
- 建 MOC（Map of Content）三维索引：按导演表 + 按题材表 + 按技法维度表（"想写什么→查哪部"）
- 研习报告用 wikilink 互链：`[[研习报告/<报告名>]]`
- 入库后**主动自检**：用户会说"自己过一遍，还有很多小问题的"——转换后必须跑全量巡检：①乱码 `\ufffd` 计数 ②控制字符 `\f/\t/\r` ③装饰残留行 ④frontmatter 完整性 ⑤H1 重复。25 份文件实测要过 4-5 轮才能真正干净

### 6. 三地同步 + 诚实声明

- 三地一致：skill references/（正本）↔ film-suite-research/（本地源）↔ Obsidian 剧本库（可检索副本）
- **诚实声明必写**：无公开剧本的（侠女/悲情城市/牯岭街/花样年华/东邪西毒）标注"影评取证非剧本原文"；流传稿标注版本差异

## 常见坑

1. **cp -r 嵌套目录**：`cp -r 源/references 目标/references` 在目标已存在时会创建 `references/references/` 嵌套——先 `rm -rf` 目标再复制
2. **相对路径写文件**：write_file 用 `../..` 相对路径会被解析到错误位置（如 Documents/AppData）——一律用绝对路径
3. **txt 全被 Obsidian 隐藏**：用户说"剧本正文没看到"= 没转 .md
4. **子代理超时≠成果丢失**：先查交付物是否已落盘（超时前写完的算数），再从日志/存档手动补写，原文摘录必须从存档 grep 不许凭记忆
5. **研习报告链接空**：`[[研习报告/]]` 是无效链接——英文文件名剧本需显式映射到中文报告名
6. **"两个标题"**：`# 文件名` H1 + 正文剧本自己的标题（如 `MEMENTO - Shooting Script`）在 Obsidian 渲染成两个标题——删 H1，文件名即标题
7. **引用块蓝条**：`> **来源**：...` 元数据在 Obsidian 渲染出蓝色竖线，排版突兀——用 YAML frontmatter
8. **cp1252 假转换**：英文剧本（pdftotext/IMSDb 抓取）常是 cp1252，utf-8 打开"能读但有 �"——必须按 2.5 编码检测，否则 600+ 处乱码藏在库里（实测断背山 604 处）
9. **frontmatter 后多余 `---`**：frontmatter 结束符已带 `---`，转换时再加一个分隔线会重复——正则清理 `^---\n(?:.*?\n)---\n\s*---`
10. **引号不配对**：YAML 值里含 `]]` 等字符时拼接易产生 `""` 双引号——替换后检查 `]]""` 残留
11. **MOC wikilink 转义**：Python 里写 `\|` 变 `\\|`（双反斜杠），链接断；表格+别名+Python 三重转义必炸——用不转义纯链接 `[[路径/文件.md]]`，生成后程序化校验（每个 `[[` 所在行含 `]]`，路径存在）
12. **华语/海外混库**：用户明确"国内的剧本和国外的本子要分开"——按内容语言分双区（中文格式归华语，含日片中文译稿），不是按片源地域
