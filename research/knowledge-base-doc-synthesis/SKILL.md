# 知识库学科文档合成（存量资产 → 密码文档）

> 从知识库已取证资产（导演卡片/技法卡片/SKILL.md 招式表/约束章节）合成新的学科密码或专题文档，零新抓取。典型场景：制作学科库《XX设计密码》批派任务、题材密码升级、知识库沉淀轮次。

## 工作流（按序执行）

1. **模板先行**：目标目录若有模板规范（如 `制作学科/00-模板规范.md`），先全文读取——它定义了文件结构（定义谱系/核心语法/范本实证/常见坑/自检清单/AI对接/来源清单/实战回写）、引用代号约定、质量纪律。不读模板直接写 = 返工。
2. **定位素材**：任务列出的素材文件可能不在预期路径——先 `ls -R` 目标 skill 目录树确认实际位置（导演卡片/深化文档/技法卡片/知识库 SKILL.md 各在不同子目录）。
3. **全量读取**：所有指定素材逐份读全文（每份都可能含关键引文与编号，只读片段会漏出处）；同一主题补 grep 检索确证术语出处（如"记忆色板"在王家卫深化文档工具4，不在花样年华技法卡片里）。
4. **引用编号写作**：按模板约定的代号体系（如 [卡·导演名]/[深·导演名]/[卡·片名#N]），每条论断带来源；诚实声明区分【通用理论】（外部理论，逐条标注）/【推断】（分析框架）/已取证（库内资产）。
5. **体积校验**：写完 `wc -c` 对照目标区间（中文 UTF-8 = 3 字节/字，见 references/zh-doc-size-and-template.md 换算表）。超上限则按压缩优先级表删减。
6. **结构校验**：压缩后 `grep -n "^#\|^##\|^###"` 确认标题层级完整（见"压缩补丁纪律"）。

## 回测三闭环（学科密码建完的下一步，必做）

学科密码/题材密码**建完 ≠ 完成**——零实战验证的新资产是"建了没用"（用户原话"先清理残留，再走回测"）。沿用题材密码三闭环：**实战 → 回写 → 修订版本号**。

- **统一虚构项目基准法**：9 份学科密码回测用同一个虚构项目（如《河底灯》90min 志怪武侠，含打斗/夜晚/妖异/山水/服化道/声音/特效全要素）做统一基准——一个项目穿全部学科，能同时验证学科间协同（同一场戏 9 学科怎么配合）。项目设定写入独立文件（一句话/类型/时长/场景/人物/冲突/主题/道具/已定基调），所有回测子代理共用。
- **回测报告结构**（对齐题材密码回测，见 `实战回测/白夜理发店_悬疑密码回测.md`）：一、项目设定速记；二、逐节对照摘要（密码的定义谱系/核心语法/范本实证/常见坑/自检清单逐节对照，验证哪些条款命中/不适用/被证伪）；三、命中清单（密码章节引用+项目证据）；四、缺口与证伪；五、回写建议（具体到章节）；六、诚实声明。
- **回写落地**：每份密码的「实战回写记录」节从"待验证"改为实际记录（哪条失效/哪条修正/新增哪条），升版本号 v1.0→v1.1。
- **回写内容源=回测报告末尾的「最值得回写 N 条」**：回测报告已给出精确到章节的回写建议（含条目表述、示例与回写位置），回写=照单 patch 落地，不是重新提炼；每套密码通常回写 3 条左右。
- **回写标注规范（题材密码 M2 回写轮实测）**：①版本行改为 `v1.1（2026-08-09，<项目>回测回写；v1.0=存量合成，2026-08-09）`；②每个新增条目行尾标【回测·<项目>】；③来源清单加一行回测报告登记；④诚实声明加「v1.1 回测回写」段——虚构项目回测必须写明"回写内容来自虚构项目回测，未经真实制作验证"。
- **回写验证**：全部 patch 后 grep 版本行 + 统计【回测· 标记数，逐套确认落盘再汇报。**版本行用全文正则检查**（`re.search(r'版本[:：]\s*v(\d+\.\d+)', txt)`），不用 `txt[:200]` 截断——版本行在 `> 版本：` 引文块里可能位于前 200 字符之后（v2.0 回写轮实战：战争/西部 2 套被截断检查误报"非 v1.1"，全文正则全过）。
- **回写批量委派（v2.0 回写轮实测）**：11 套密码回写不必 1 子代理/套——**分 3 个子代理（3/4/4 套）合并批派**，每代理读对应回测报告→patch 目标密码→升版本→标注【回测·项目】→汇报；每套只归一个子代理保证互不覆盖，完成后主线程全量版本校验（11 套全 v1.1）再进发布。
- 回测子代理批次：每学科一个子代理（9 份=9 个并行），各自写独立回测文件（如 `学科回测-20260809/<学科>_回测.md`），避免互相覆盖；报告写入 `_work/` 暂存区，验证后归入知识库 `实战回测/`。

## 引用真实性系统核查（子代理产出验证，不抽检）

子代理批量合成的文档，引用**必须系统验证而非抽检**（本会话 732 处引用全查）。解析规则要宽容：

- **别名/简称映射**：「小津」=小津安二郎、「聊斋原著」=聊斋志异_原著
- **连写拆分**：「深·昆汀工具7」=导演名"昆汀"+"工具7"（无空格连写）；「深·小津 2.3」=导演名+章节号
- **前缀匹配**：「卡·无间道 双卧底镜像开场」=片名+描述后缀
- **姊妹文档引用**：「卡·色彩设计密码」是调色密码引用姊妹文档（非技法卡片）——识别并放行，来源清单已声明映射
- 解析失败 ≠ 造假：先按上述规则二次解析，剩下的才是真问题。验证脚本用 Python（中文路径 search_files 不可靠），对照 `references/大师技法卡片/`+`导演美学卡片/` 实际文件名。

## 下游 skill 接入检查（层建设后必查）

知识库新增资产层（如第五层制作学科库）后，**必须检查下游创作 skill 是否引用新资产**——5 个创作 skill（AI电影编剧/AI电影导演/AI短剧编剧助手/AI短剧导演助手/AI提示词助手）各加一步「定学科」（导演类加光影/构图/声音/剪辑/调色/视效，编剧类加服化道/美术/色彩/声音，提示词类加全部学科密码的 AI 对接节）。漏这一步 = 知识库建了但创作树不知道 = 白建。

**过时数字扫描**：skill 内嵌的索引快照（如"大师技法卡片37部"）会过时——每轮层建设后 grep 各创作 skill 的数字声称（技法卡片N部/导演N位/题材密码N套），与知识库实际对齐；「招式速查 16 条」是设计值（内置常驻子集）非过时值，勿误改。同步后升级各 skill patch 版本。

## 二手资产转引纪律（写作时必守，非事后核查）

导演卡片/手法深化/技法卡片等**库内二手合成文档只是索引**——它们指引出处（如 S2=存档 lau_soc.txt），但其中的摘录与数字是转述，**不可直接转引**。规则：

- 每条原文摘录必须回**原始存档文件** grep 逐字验证（编号体系指向的 pages/ 存档），不许抄导演卡片里已引过的段落就算数。
- 二手文档里的**派生数字/总结句**（如"开合各 20 分钟复仇情节"）若无存档直接依据，降级为存档可验证的原文表述（实例：降级为 "opens and closes with a perfectly serviceable plot"），或标注"导演卡片转述，存档未验证"。
- 引用编号可沿用导演卡片体系并扩展（如新增 S15=波德维尔 2022《The dragon still dances》存档，导演卡片未收录该文件），但新增编号必须在来源清单注明文件与内容。

## 中文路径检索坑（本机实测，必读）

`search_files`（ripgrep 后端）对中文路径（如 `C:\...\skills\妖玉影视\_知识库\...`）会返回 0 结果或 IO error（os error 3）。**凡涉及中文目录/文件名，直接用 terminal（git-bash）的 `ls -R` / `grep -n` / `wc -c`，不要用 search_files**。该用户知识库全中文命名，此坑每轮必踩。

## 中文 Markdown 体积纪律

- UTF-8 下中文 1 字 ≈ 3 字节，目标"12-18KB" ≈ 4000-6000 汉字 + 结构开销。判断是否达标先 `wc -c`，别靠感觉。
- 同库既有文档是校准基准：题材密码 9.6-38KB 不等（志怪 18.5KB 为富文档标杆）——"约 N KB"允许小幅越界，但超过上限 15%+ 必须压。
- 压缩优先级（从实战得出，按此顺序砍，保住强制覆盖）：
  1. 来源清单表格 → 紧凑段落（代号+文件名+引用内容合一行，可省 1-2KB）
  2. 小表格（3-6 行）→ 内联进定律/正文行
  3. 提示词示例/模式示例删到最少必需（可推导的合并为一条并指向正文小节）
  4. 相邻子弹合并（反讽律并入仪式感、色域变奏与沙漠极值合并）
  5. 范本实证表压缩单元格（出处保留代号，时机列用短词）
  6. 定律行、落地行的冗余措辞
- 底线：模板要求的小节（常见坑=症状+根因+修法、自检清单、范本表）和任务点名的主题不可删——内容下限由任务覆盖决定，压不动就如实报告偏差，不假装达标。

## 压缩补丁纪律

多轮 patch 压缩中文文档时：old_string 必须完整包含要删的整块（含标题行/空行），否则容易误删标题或把两行焊成一行（本会话两次翻车：删掉了"## 二、核心语法"标题、把 2.5 定律与首条子弹合并）。每批 patch 后立即 `grep -n "^#\|^##\|^###"` 校验结构；发现误删马上用反向 patch 恢复，别拖到收尾。

**中文文档 patch 一律用 replace 模式，慎用 V4A 批量模式**：中文 Markdown 满是 `"` 引号，V4A 多 hunk patch 会触发 escape-drift（报错提示 old_string 含字面 `\"` 序列与文件不匹配，整批拒绝、零文件修改）。实测：V4A 首调用失败后转 replace 模式逐条 patch 全部成功。规则：old_string/new_string 里直接写 `"`，不要反斜杠转义；V4A 只留给无引号的纯 ASCII 批量场景。

## 质量纪律

- 每条论断带来源，引用代号按模板约定（模板未定义的知识库 SKILL.md 引用可自定 [知识库·招式表] 等并在来源清单解释）。
- 诚实声明三档：外部通用理论标【通用理论】；分析框架标【推断】；库内已取证资产直接引用编号。
- 实战回写（如伏妖记颜色语义体系）标注日期与来源，不冒充外部文献。
- 交付后检查目标库索引是否需要登记新文档（如知识库 SKILL.md 的制作学科索引）——目标库若为 user-owned skill，不要擅自改，在总结里提示父代理/用户处理。
