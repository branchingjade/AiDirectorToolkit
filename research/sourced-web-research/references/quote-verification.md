# 研习报告/技法卡片 引文全量校验协议（2026-08-07 未麻的部屋轮实测）

场景：写完《研习报告》《技法卡片》等带 [研S#] 引文编号的交付文档后，把文档里的每一条引文
逐字对回 pages/ 存档源文件，目标 **0 MISS**。工作区已有大量同类校验脚本（`pages/_verify_*.py`），
本文件是该协议的可复用配方。完整可运行样例：`pages/_verify_kon_pb.py`（未麻轮，256 条提取 / 184 命中 / 72 豁免 / 0 MISS）。

## 引文提取：三类，只认带标签的行

对 md 文档逐行处理，**仅当行内含 `[研S#]` 类标签**才提取：

1. **反引号** `` `...` ``（原文摘录块）；内容含 `/` 的是文件路径（如 `pages/kon_pb_*`），跳过。
2. **块引用行**（`>` 开头）：取行内平衡「」片段 + 反引号片段；两者皆无则该行是底本说明，跳过。
3. **正文行内「」**：深度法提取**平衡**「」片段（含嵌套，如 「「レクイエム〜」ではまた「赤いドレス」」が…」 取最外层）；
   长度 <2 的（如空「」）跳过。

规则：
- **表格行（`|` 开头）跳过**——那是摘要，不是引文；表格里的「」是自撰术语。
- 标题行/无标签行天然跳过。

## 语言感知归一化（核心技巧）

归一化不对，再认真的校验也是假绿。三条规则：

| 语言 | 判定 | 归一化 |
|---|---|---|
| 日文 | 引文含假名（`[\u3040-\u30ff]`） | **去全部空白**（不折叠！）——日文无空格，源文件换行会把单词劈开（如「爆笑させてもらっ\nた」折叠后变「もらっ た」匹配失败）；引文与源文件都 strip 全部空白 |
| 中文/英文 | 其余 | 折叠空白为单空格 |
| 英文源 | — | 额外**剥 markdown 强调符 `_` `*`**（`_Perfect Blue_`、`_I'm feeling pathetic..._`）再折叠空白 |

统一处理：**弯引号转直**（`“”`→`"`，`‘’`→`'`）；`''`（维基斜体标记）保留原样。
**加强版（2026-08-09 逍遥骑士轮实测）：引号字符全部移除**（`'` `"` 弯直都删）——引文用单引号、源用双引号（`'Easy Rider'` vs `"Easy Rider"`）也能匹配；单词内撇号（`it's`、`rock 'n' roll`）两端一起删，不影响一致性。比「弯转直+照抄源」更省事，推荐直接全移除。

匹配 = 归一化后引文是归一化后源文件的**子串**。注意子串匹配的边界：引文尾部标点必须与源一致
（源是 `thrill," he later wrote` 就引用到 `huge thrill` 为止，别加句号）。

## 失配陷阱目录（实战踩过，按频率排）

1. **源文件换行劈词**（日文）→ 日文模式 strip 全部空白解决。
2. **markdown 强调符残留**：`_Perfect Blue_` / `**[…]**` 剥 `_*` 解决；但 `_Requiem for a Dream _?` 这种
   强调符后带空格的，剥符后仍留空格（`Dream ?`）——引文绕开该片段或拆分引用。
3. **繁简中文不一致**：中维是繁体（「特別監查員」「夢與現實」），引文照源文件逐字，别按简体写。
4. **引号类型混用**：源用「」你写『』、源用 `"` 你写 `'`（含弯直引号），全部按源。
5. **全角/半角标点**：`No，I'm real` 的全角逗号照抄。
6. **省略号长度**：`…` 与 `……` 之别；改稿记录清单里第一条是 `……`、其余是 `…`。
7. **引文里插了自己的字**：如把「というセリフで…」写成「というセリフで例の…」丢字——逐字照录源。
8. **源站排版讹误**：源文件本身错（「SIMCITY]」右括号是 `]`）——引文**照抄错字**，注释放引号外。
9. **标签张冠李戴**：引文出自 A 文件却标了 B 的编号——校验脚本按标签映射源文件，MISS 即暴露；
   新引用的存档记得加入 S_MAP（本次补了研S25/研S26）。
10. **译文/注疏混在「」里**：自己的翻译（「模拟未麻」「没回本」）或自撰术语（「省略蒙太奇」「辨真尺」）
    会被行内提取器当成引文——**显式豁免表**（脚本 IGNORE 集合，输出时逐条列出），不要静默跳过，
    这样校验报告能自证哪些是引文、哪些是注疏。
11. **多来源标签行错位（2026-08-09 实测）**：交付行内标 `[S4][S5]` 两个来源，自动提取器把片段归给
    行内第一个编号，但片段实际出自另一个来源（引文跨源复用）→ 校验对「行内标注来源」失败后
    **用全部源文件兜底匹配**，命中任一即 PASS；手工清单再钉死每个片段的规范来源。判别标准：
    片段原文存在于至少一个存档源 = 验证通过，标签只是定位线索。
12. **省略号拼接两个独立引句（2026-08-09 实测）**：把源里两处分开的话用 `…` 拼成一句引用
    （`"You're such a cruel mother… I hate you so much"`）必然 MISS——源里两句之间隔着叙述。
    改法：拆成两个独立引号片段 `"A"……"B"`，各验各的。
13. **无引号块引用按句拆分**：块引用若整段是多句且句间在源里不连续（或引文是节选），按
    `(?<=[.!?])\s+` 拆句逐句校验，避免整段子串匹配失败误报。英文行加 ASCII 占比 >0.8 过滤，
    防止中文说明行被误当引文提取。

## 迭代闭环

1. 写文档 → 2. 脚本提取校验 → 3. MISS 分类：真引文问题→改文档引文对齐源；译文/注疏→入 IGNORE 表；
   标签错→改编号或补 S_MAP → 4. 重跑直到 0 MISS → 5. 把「提取/命中/豁免/MISS」数字写进文档的
   ⚠️ 诚实声明·校验记录段（未来读者可见可复验）。
