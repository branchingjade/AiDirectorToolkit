# Obsidian 素材/文献归档库建设（剧本库案例）

> 场景：把抓取的外来素材（剧本/文档/PDF 提取文本）建成 Obsidian 可检索的归档库。
> 实战案例：2026-08-06 剧本库（25 份剧本原文 + 37 份研习报告 + MOC 三维索引）。
> 教训来源：用户三次纠正（不可见/标题重复/排版错乱）——本文件是修复后的正确流程。

## 一、铁律：Obsidian 只索引 .md

**Obsidian 默认只显示 .md 文件，.txt 全部不可见。** 抓取素材以 .txt 入库，用户打开库是空的（"知识库中剧本正文没看到"）。

- 入库前必须转 .md：Python `content = open(f, encoding=...).read()` 后写 .md
- **编码探测法（关键）**：英文剧本/PDF 提取文本多为 cp1252/latin-1。**不能靠 try/except 抛错判断**——UTF-8 带 `errors="replace"` 时 cp1252 文件会"解码成功"但产生数百个 �（实战：断背山 604 处、七武士 2 处、血色将至 89 处）。正确做法是**对比两种编码的乱码数，取乱码少的**：

```python
raw = open(src, "rb").read()
n_utf8 = raw.decode("utf-8", errors="replace").count("\ufffd")
n_cp = raw.decode("cp1252", errors="replace").count("\ufffd")
enc = "cp1252" if n_cp < n_utf8 else "utf-8"   # 乱码少的胜出
text = raw.decode(enc)
```

- **入库后全库乱码复检**：所有 .md 再扫一遍 `content.count("\ufffd")`——早期用 utf-8 转过的文件可能带着隐藏乱码，`\ufffd` 是唯一可靠的乱码指纹（不是依赖单个文件的报错）

## 二、元数据用 YAML frontmatter，不用引用块

**引用块（`>`）在 Obsidian 渲染成蓝色竖条，丑且不可搜索。** 元数据必须用 YAML frontmatter（Obsidian 原生属性面板：可折叠、可搜索、可排序）。

```yaml
---
来源: "IMSDb（imsdb.com/scripts/Fargo.html）"
版本: "科恩兄弟流传稿"
与成片差异: "与上映版基本一致（自编自导）"
可信度: "🟢 流传稿≈拍摄稿"
抓取日期: "2026-08-06"
研习报告: "[[研习报告/冰血暴_研习报告]]"
---
```

**frontmatter 字段命名不要混入 markdown 语法**——字段值只放 `[[wikilink]]` 裸链接，不要放 `**研习报告**：` 加粗前缀（会被塞进属性值，产生多余引号/脏值）。写入后校验 `]]""` 这类多余引号。

## 三、不要加 `# 文件名` H1 标题

**Obsidian 用文件名当页面标题。** 文件里再加 `# 文件名` 会和正文第一个标题（素材自己的标题页）形成"两个标题"。

- 文件名即标题：`记忆碎片_剧本_拍摄稿.md` 显示为"记忆碎片_剧本_拍摄稿"
- 正文直接从素材自己的标题开始（如剧本的 `MEMENTO - Shooting Script` 标题页）
- 修旧文件：`re.sub(r'^# .*\n\n', '', content, count=1)` 删掉加的 H1

## 四、PDF 提取残留必须清理（排版错乱的根因）

pdftotext/转录文本带三类残留，Obsidian 渲染时直接"排版错乱"：

| 残留 | 示例 | 清理 |
|---|---|---|
| 分页符 `\f` | 每页结尾 | `content.replace("\f", "\n")` |
| ASCII 装饰行 | `--- .·.`、`(._`、`\.`、`^ --`、`............ ?` | 正则删纯符号行（含全角符号 `·`） |
| 网页 JS 残留 | `if (window != top) top.location.href=...` | `re.sub(r'\n*if \(window\s*!=\s*top\)[\s\S]*?// -->\s*\n+', '\n', content)` |

**保留合法分隔符**：`***`（剧本场景分隔惯例）、`---`（markdown 分隔线）、`...`（省略号）。删除正则必须白名单豁免：

```python
if re.fullmatch(r'-{3,}|\*{3,}|_{3,}|\.{3,}', stripped):  # 合法分隔符，保留
    cleaned.append(l); continue
if pattern.fullmatch(stripped):  # 纯符号装饰行，删除
    continue
```

**清理后合并连续空行**：`re.sub(r'\n{3,}', '\n\n', content)`。

## 五、非官方材料必须标注版本可信度（文献完整性）

抓来的剧本/文档多数不是"官方原版扫描件"，用户（从业者）会直接看出"不完整、不规范、和原本不一样"。**必须在 frontmatter + MOC 分级表里诚实标注**：

| 级别 | 含义 | 处理 |
|---|---|---|
| 🟢 原稿/拍摄稿 | 编剧原稿或接近成片的拍摄稿 | 可当拍摄稿引用 |
| 🟡 流传稿/译稿 | 流传稿或署名译者译本，与成片有出入 | 引用前核对 |
| 🟠 早期稿/整理稿 | 与成片差异大，或非原稿的整理稿 | **不可直接当拍摄稿引用** |
| 📄 原著对照 | 非剧本，为改编来源 | 单独标注 |

frontmatter 的 `与成片差异` 字段写关键差异（如"七宗罪 1992 早期稿无盒子反转"），完整差异在研习报告诚实声明里。

## 六、档案结构（剧本库参考）

**华语与海外分库**（用户明确要求"国内的剧本和国外的本子要分开"）——两种剧本格式（国内 `第N场 地点 时间 内外` vs 海外 `INT./EXT.`）混在一个目录不可用：

```
Obsidian Vault/剧本库/
├─ 剧本库MOC.md          ← 三维索引（导演表/题材表/技法维度表）+ 可信度分级表
├─ 华语剧本/              ← 国内标准格式（中文剧本 + 华语片研习报告）
│  ├─ 剧本原文/ 5 份
│  └─ 研习报告/ 15 份
└─ 海外剧本/              ← INT./EXT. 格式（英文剧本 + 海外片研习报告）
   ├─ 剧本原文/ 22 份
   └─ 研习报告/ 22 份
```

**分类逻辑**：按**剧本内容语言**分（不是按片源国别）——婚姻故事中文译本归华语、英文拍摄稿归海外；日本片的中文译稿（摄影机不要停）归华语。无剧本的华语片（倩女幽魂等）研习报告也归华语区。分库后**必须同步更新 frontmatter 里的研习报告 wikilink 路径**（`[[研习报告/X]]` → `[[华语剧本/研习报告/X]]`）。

**MOC 是检索入口**：按"想写什么 → 查哪部"倒排（群像戏→七武士/木兰花），比按文件名搜索快。MOC 里链接到 .md 的引用要与实际文件名一致（英文文件名→中文报告名需显式映射）。

### MOC 批量生成的坑（wikilink 转义）

1. **markdown 表格里 wikilink 的 `|` 别名分隔符会被表格语法吃掉**——要么不用表格（用列表 `- 片名：[[路径/文件名.md]]`），要么用 `\|` 转义
2. **Python 生成时 `\|` 会被转义成 `\\|`**（文件里存了两个反斜杠）——Obsidian 不认识，链接失效。用 `chr(92)+"|"` 构造，或干脆**避免在表格里用带别名的 wikilink**（直接裸 `[[路径]]` 最稳）
3. **生成后必须校验链接有效性**：正则提取 `\[\[(华语剧本|海外剧本)/([^\]]+)\]\]`，逐个 `os.path.exists` 检查，缺失即修

## 六·五、全量巡检清单（入库/修库后跑一遍）

25 份文件四类问题全查，输出"完全干净"才算完：

1. **frontmatter 完整**：`^---\n(.*?)\n---\n` 匹配 + `来源`/`版本`/`与成片差异`/`可信度`/`抓取日期` 字段齐 + 引号配对（`fm_body.count('"') % 2 == 0`）
2. **乱码**：`content.count("\ufffd")` 全库扫描（含研习报告/MOC，不只剧本原文）
3. **控制字符**：`\f`（分页符）、`\t`（tab，IMSDb 页脚常见）、`\r`——全清
4. **装饰残留行**：纯符号行（含全角 `·`）且非 `---`/`***`/`___`/`...` 白名单——全删
5. **无 H1 残留**：前 20 行无 `# ` 开头（文件名即标题）
6. **MOC 链接**：全部 `[[...]]` 指向存在的文件

修复顺序：先删 H1 → 清控制字符 → 编码重转 → 清装饰 → 修 frontmatter → 校验。每步后跑一遍对应检查，最后全量复检。

## 七、批量处理的坑

1. **正则必须宽松匹配编码变体**：`window != top`（带空格）和 `window!=top`（无空格）都存在——用 `window\s*!=\s*top` 一次覆盖
2. **f-string 里不能有反斜杠**（Python 3.11 前）：`f'"{m.group(0)[len("...\"")]}"'` 会 SyntaxError——拆开用字符串拼接
3. **相对路径 write_file 会解析错**：`剧本库\..\..\..\AppData\...` 会落到 `C:\Users\HMSJ\Documents\AppData\...`——skill 文件写入一律用绝对路径
4. **转换前先确认源文件真身**：看似 .txt 的存档可能是 0KB 空壳（如 `rashomon_ia.txt`），用 `find -size +10k` 找真源
5. **重复文件先删再入库**：同名/同大小文件（如两杆大烟枪清洗版≈final-script）入库前对比大小
6. **转换后全量校验 frontmatter**：`---` 开头 + `来源:`/`版本:`/`可信度:` 在首 200 字符内；`re.match(r'^---\n(.*?)\n---\n', c, re.S)` 且 rest 不以 `---` 开头（frontmatter 结束符与旧分隔线叠加会产生多余 `---`）
