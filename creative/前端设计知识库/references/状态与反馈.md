# 状态与反馈

> 2026-08-10 | 面向：工具型 UI 的加载/空/错误/成功状态设计。状态设计 = Nielsen #1（系统状态可见）的完整落地。
> 来源标注：训练知识（NN/g 进度指示研究、Material Design 3、Nielsen 10 启发式）

## 一、状态全景（一个界面该有的状态）

| 状态 | 什么时候出现 | 核心要求 |
|---|---|---|
| 默认态 | 正常展示 | 信息完整、层级清晰 |
| 加载态 | 数据未到 | 见下「加载态」 |
| 空状态 | 无数据/无结果 | 见下「空状态」 |
| 错误态 | 请求失败 | 见下「错误态」 |
| 成功反馈 | 操作完成 | 见下「成功反馈」 |
| 禁用态 | 条件不满足 | 置灰（WCAG 豁免对比度） |

## 二、加载态（Loading）

| 模式 | 什么时候用 | 出处 |
|---|---|---|
| 骨架屏（Skeleton） | 页面/区块首次加载，内容结构已知 | NN/g, "Skeleton Screens" 研究 |
| 转圈 Spinner | 不确定时长的小操作（按钮提交中） | NN/g "Progress Indicators" |
| 进度条 | 确定时长/百分比（上传、批量任务） | 同上 |
| 乐观更新 | 操作几乎必然成功时先更新 UI 再请求（开关、收藏） | NN/g, "Optimistic UI" 实践 |

要点：
- **骨架屏 > 转圈**：骨架屏提前告知布局结构，用户感知更快（NN/g 实测）
- 加载超过 1 秒要有进度提示，超过 10 秒要允许取消（NN/g 进度指示原则）
- 骨架屏用明暗闪烁，别用转圈塞满全屏

## 三、空状态（Empty State）

| 层级 | 做法 | 出处 |
|---|---|---|
| 三件套 | 图标 + 一句话说明 + 一个动作（创建/刷新/清除筛选） | NN/g, "Empty States" 研究 |
| 有筛选时 | 区分「真没数据」和「筛选无结果」——后者给「清除筛选」按钮 | 同上 |
| 首次使用 | 引导性文案 + 主操作（「添加第一个项目」），不写「无数据」 | 同上 |
| 别写 | 「暂无数据」「404」裸文本——用户不知道下一步 | 同上 |

## 四、错误态（Error）

| 规则 | 逻辑 | 出处 |
|---|---|---|
| 就地展示 | 行内错误贴近出错处，全局错误用顶部横幅 | Material Design 3, "Banners" |
| 具体 + 可行动 | 说原因 + 给动作（「网络超时，重试」），不说「出错了」 | Nielsen #9 |
| 重试机制 | 失败操作给重试按钮，且自动重试一次（网络抖动常见） | 工程实践 + Nielsen #9 |
| 保留上下文 | 报错不清空页面已有内容 | Nielsen #9 |
| 错误颜色 | 红色 + 图标/文字双通道（不只靠颜色） | WCAG 1.4.1 |

## 五、成功反馈

| 模式 | 逻辑 | 出处 |
|---|---|---|
| Toast/Snackbar | 轻量成功（已保存、已删除）——不打断当前操作 | Material "Snackbars" |
| 行内状态 | 保存成功在字段旁短暂显示 ✓ | Material "Text fields" |
| 全屏成功 | 只有关键流程完成才用（导出完成、提交成功页） | NN/g 反馈层级 |
| 反馈时机 | 立即反馈，别等用户找 | Nielsen #1 |

**不滥用**：每次操作都弹 toast = 噪音（NN/g「反馈疲劳」）。可逆操作（开关切换）本身状态变化就是反馈，无需 toast。

## 六、状态实现的工程要点

| 要点 | 说明 |
|---|---|
| 状态机 | 每个组件/页面显式定义 loading/error/empty/success 四态，禁止隐式状态 |
| 请求竞态 | 快速切换时旧请求响应覆盖新状态——用请求序号/AbortController 丢弃过期响应 |
| 重试与缓存 | 失败重试带退避；已加载数据切换回来不重新加载（记忆 + 缓存） |
| 骨架屏实现 | `prefers-reduced-motion` 下关掉骨架闪烁动画（见 [[可访问性与跨屏适配]]） |

## 实战对照（本工作区偏好 → 权威依据）

| 既定偏好 | 依据 |
|---|---|
| 无限滚动「加载更多」按钮 | 加载态 + NN/g 无限滚动（按钮形式比自动加载可控） |
| 批量操作有反馈 | 成功 toast + 行内状态 |
| 记忆上次选择状态 | 缓存/记忆 = 避免重复加载 |
| 功能不做半成品 | 状态设计四态齐全 = 成品标准之一 |
