# MoA 参考模型行为规范（2026-07-21 豆包语音API抓取复盘）

## 核心原则

**参考模型是顾问，不是指令源。聚合器必须用自己的判断做决策。**

## 失败模式

### 模式1：把参考分析当指令执行

多个参考模型给相反方向时（一个说并行、一个说串行），我试图同时满足所有人 → 决策瘫痪。

**正确做法：** 选最符合已验证经验的方向，不试图同时满足所有人。

### 模式2：MoA 关了问题仍在

关闭 MoA 后问题仍然存在，说明根因在我——没有用聚合器的角色做独立判断。

### 模式3：参考模型说"还有更好的"就改道

已验证过的工具就信任到底。参考模型说"还有更快的方法"时，先问用户当前速度能否接受。

## 配置问题

### 顶层冗余字段

```yaml
moa:
  presets:
    default:
      reference_models: [...]  # ← 正确位置
  reference_models: [...]      # ← 冗余，设置页面bug
```

设置页面保存时会同时写两份。需要手动清理顶层冗余：
```bash
hermes config unset moa.reference_models moa.aggregator moa.max_tokens moa.fanout moa.enabled
```

### 聚合器 ≠ 参考模型

聚合器不应该是参考模型之一。自己评自己无法客观审视。当聚合器（如 deepseek-v4-pro）也是参考模型时，会自我放大——聚合器无法客观评估自己的建议。应该用不相关的模型做聚合器。

### 参考模型多样性

仅 2 个 provider（xiaomi + deepseek）的参考模型多样性不足。边际收益递减。建议增加到 3 个不同 provider。

### fanout 模式

`per_iteration` 每轮都调用参考模型，简单问答也全额支付。评估是否需要降级为 `per_task`。

## 模型切换影响

| 模型 | 行为特征 |
|------|---------|
| deepseek-v4-pro 作为聚合器 | 更容易被参考模型左右（自己=聚合器） |
| mimo-v2.5-pro 独立 | 更独立，但分析过多、执行不足 |

## 用户纠正响应

用户说"不是MOA的问题"时 → 停止分析MoA，回到任务本身。

## 决策规则

```
参考模型分析 → 聚合器读取 → 聚合器用自己的判断决定
                                     ↓
                              参考模型给相反方向？
                                     ↓
                      选最符合已验证经验的，不试图同时满足
```
