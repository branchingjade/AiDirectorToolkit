## 一、生成预算管理

### 1.1 段数估算：450-900 段（计算）

- 90-120 分钟 = 5400-7200 秒；按 8-12 秒/段：5400/12=450，7200/8=900 → **一部 90-120 分钟电影约需 450-900 段**。【计算】
- 8-12s/段是内部制作规范（S20：Seedance 单段硬上限 30s，建议 8-12s）；行业选型测试也普遍固定"5 秒或 10 秒"作为输出时长（S15）。**若按 5s/段，段数将翻倍至 1080-1440 段**，成本与一致性风险同步放大。【推断】
- 模型能力印证：Seedance 2.0 支持自定义输出规格（分辨率/宽高比/时长，含 21:9）（S8）；MiniMax H3 最高 15s/2K（S17）；可灵 3.0 为 API 视频生成主力（S10）。段时长选择受"单段承载单一任务"约束——见 2.2。

### 1.2 失败率与重试策略（无官方数据，行业叙述+推断）

- **"抽卡"是常态**：制作人透露"AI生成视频无法一次到位，存在极高的废片率……光影崩坏、人物变形是常态"，"很多时候只能选出'瑕疵最少的镜头'而非绝对完美的镜头"（S14）。
- 实测数据点：36氪用可灵 3.0 做《霸王别姬》压力测试，复杂战斗镜头"经数十轮测试，不同版本的输出效果差异较大"；5 轮测试中"走上舞台"语义可稳定完成，但"从侧方上台"动线不可稳定复现，偏差出现在第 7 秒前后的路径衔接处（S18）。
- **确定性规律**：单目标短镜头 >> 多道具/多人/跨空间长镜头（S18）；"连续生成 10 条以上，人物就开始飘"的模型不适合产线（S15）。
- 重试代价：一次重渲需要 4-6 小时（S14）；生成一条 15s 4K 视频约 114 元算力、1080p 约 47 元（S14）。
- **预算建议（推断）**：按"选中率 20-50%"预留生成量，即 450-900 段的有效成片需准备约 1000-4000 次生成调用；对动作/战斗/群像场景单独加预算倍率。【推断】

### 1.3 成本基准（可验证数字）

| 项目 | 数字 | 来源 |
|------|------|------|
| Seedance 2.0 720p 无视频输入 | 0.99 元/秒（46 元/百万 token） | S16 |

- 按 0.6-1.0 元/秒毛估：90 分钟有效成片 5400s × 2-5 倍废片率 × 单价 ≈ **0.65 万-2.7 万元**（仅画面生成，不含声音/后期/人力）。【计算+推断】
- API 并发决定批量速度：火山引擎年框 1000 万元 ≈ 400 并发、500 万 ≈ 200 并发；无并发支持则排队/超时（S16）。Seedance 官方 API 采用异步任务+30 秒轮询模式（S8），批量生成需自建队列。

### 1.4 批量生成管理方法

- **管线化**：Runway Workflows 官方给出节点化方案——"chain multiple generations together"（链式多次生成）、可复用模板、分支变体实验、"automate repetitive tasks"（自动化重复任务）；LLM 节点可"automate prompt engineering and maintain consistency across multi-step generations"（跨多步生成保持一致性）；媒体工具节点支持拼接视频、抽取首/中/尾帧、加/抽音频（S12）。
- **平台级批量能力**：可灵 Image 3.0 官方标注 "series generation & batch optimization"（系列生成与批量优化）（S10）。
- **分批/进度/抽检（推断）**：按幕/场分批（内部规范即按 幕→场→段 组织，S20），每批任务表驱动（分镜号→提示词→参考资产→任务 ID→产物 URL 的映射表），按批抽检选中率与一致性，不合格段打回重生成；记录每段的 seed/参数便于复现。【推断】
- **选型纪律**：用"同一分镜对比法"固定变量（同一分镜图/参考视频/同 Prompt/同输出时长 5s 或 10s），只换模型，记录画面效果/一致性/生成耗时/单次成本，写入团队 wiki（S15）；避免绑定单一平台导致切换成本（S15）；火山方舟是 Seedance 视频生成 API 的唯一官方渠道（S19）。

## 二、剪辑方法论：几百段 AI 片段如何组装成电影

### 2.1 剪辑表 EDL 概念（可验证）

- EDL 是后期剪辑中的有序列表，"包含 reel 和时间码数据，指明每个视频片段从何处获取，以便 conform（合板）最终成片"（S1）。离线剪辑系统产出 EDL，在线剪辑系统据此自动合板；格式从简单 CMX3600 到 AAF/XML（S1）。ElevenLabs 配音工具可直接输出 AAF（时间线数据），说明 AI 工作流已能衔接传统 EDL/AAF 生态（S13）。

### 2.2 从分镜到剪辑表：拆解式工作流（36氪一手实测+S20 内部规范）

- **核心方法论**（S18，可灵 3.0 实测结论）：
  1. **单镜头承载单一任务**——一个镜头只完成一次清晰动作，避免长镜头中的形态偏差；
  2. **动作链拆段**——"冲锋、挥剑、击中、敌人受力、倒地、追兵包围"不靠单个镜头，拆为独立镜头，再用音效与剪辑让观众感知完整战斗；
  3. **空间路径拆节点**——"后台→侧台→舞台"每个节点独立镜头，或为关键转折分别设置首尾帧；实测证明"将后台、侧台与舞台拆分为两个镜头，通过人物朝向、视线引导与剪辑手法，构建空间连续性"优于单镜长镜头；
  4. 分工原则："**AI 负责镜头生成，创作者负责任务拆解、连续性构建与最终效果判定**"。
- 内部规范（S20）的 幕→场→段→镜 四层结构天然形成剪辑表骨架：段=剪辑单元（8-12s），镜=段内切点（"切"字标记），分镜文档本身即可转成 EDL 字段（段号/起始帧/参考资产/提示词）。【推断+内部约定】
- 传统剪辑理论支撑：连续性剪辑（continuity editing）追求"coherent and smooth storytelling"，依赖一致的画面质感、平衡构图与受控的剪辑节奏（S2）——这正是 AI 分段生成后要重建的东西。

### 2.3 节奏控制（可验证+内部规范）

- "镜头时长决定整片节奏，剪辑者通过调整镜头相对长度控制节奏，制造特定效果与强调"（S2）。快切（fast cutting）制造紧张、慢剪（slow cutting）/长镜头制造压迫与沉思；蒙太奇传统（爱森斯坦：两镜碰撞产生第三含义）vs 长镜头传统（巴赞：尊重时空连续）是节奏设计的两个极点（S2）。
- 内部规范落地（S20）：关键情绪给长镜头（"太久了"的静默镜头是资产）、爆发前留安静镜头、变速必须有叙事理由；节奏曲线在三幕层面规划。
- AI 语境下的节奏特点【推断】：动作戏用 1-2s 的短镜快速拼接（每段 8-12s 内可含 4-6 个快切），情绪戏整段慢放不切；受"单段单任务"约束，快切序列需要更多段数预算。

### 2.4 AI 生成片段的接缝处理

- **画面接缝**：图生视频-首尾帧（`role=first_frame/last_frame`）强制段与段首尾画面一致；多模态生视频也可通过提示词指定参考图作为首/尾帧（S8）。`return_last_frame` 返回本段尾帧图，直接作为下一段的首帧输入（S8）——这是官方提供的"段间无缝衔接"机制。
- **瑕疵修补**：Seedance 2.0 支持"编辑视频"（替换主体、增删对象、局部重绘/修复），可对生成瑕疵做局部修补而非整段重渲（S8）。
- **剪辑层面的接缝**：转场手段（dissolve 溶镜、wipe 划像、jump cut 跳切、match cut 匹配剪辑等）在传统剪辑中承担接缝功能（S2）；AI 电影中接缝问题更多靠"首尾帧锁画面 + 视线/朝向引导 + 音效桥接"解决（S18 实测：音效与剪辑让观众感知完整动作链）。
- **工具链**：Runway Workflows 提供 "Stitching videos together"（拼接视频）等媒体工具节点，可把分段产物自动化拼合（S12）。
- **后期一体化趋势**：MiniMax H3 宣称把"后期"装进模型——画面、旁白配音、字幕、动效一次生成直接交付（S17），这会压缩传统接缝处理工序，但长片仍需要剪辑层做叙事组装。【推断】

## 三、跨段一致性：同一角色的脸/服装/场景跨段稳定

### 3.1 现状判断

- 行业共识：**跨集/跨段角色一致性仍是技术难点**——"目前主流 AI 视频模型（如可灵、通义等）尚无法保证第 30 集男主与第 1 集的脸完全一致"（S14）；但"人物稳定以后，不同地点、景别和情绪的镜头才具备剪辑进同一段叙事的基础"（S18）。
- 行业普遍组合拳："**LoRA 微调 + 角色参考图池**"硬扛一致性（S14）——涉及反复训练与重渲，是算力大头（S14）。

### 3.2 平台级一致性能力（可验证）

| 方法 | 机制 | 来源 |
|------|------|------|
| 角色参考图/多图参考 | Seedance 2.0 多模态参考：图片 0-9 张 + 视频 0-3 + 音频 0-3，组合参考（图+音频/图+视频/图+视频+音频），"保持稳定角色特征" | S8 |
| 首尾帧 | 图生视频-首尾帧强制首尾帧与指定图一致 | S8 |
| 主体绑定 | 可灵 3.0 主体绑定：实测项羽/虞姬/戏子跨镜头保持人脸、服饰、身份一致；"解决叙事的基本问题：保障角色的可识别性" | S18 |
| 元素参考 | 可灵 3.0 Omni：element reference，"high consistence and precise prompt adherence" | S10 |
| 人脸库 | 火山引擎"人脸库权限"随年框价格分级——买的是更多可用的合规人脸资源，避免"AI 人脸"重复 | S16 |
| 多模态复合参考 | MiniMax H3：人物参考图+镜头运动参考视频+参考歌声音频一次生成 | S17 |
| 音色参考 | Seedance 音频参考（reference_audio_url），角色音色绑定 | S8、S20 |

### 3.3 ControlNet 与条件控制（可验证，图像层通用机制）

- ControlNet 是"通过增加额外条件来控制扩散模型"的网络结构：把网络块复制为"locked"（锁定）与"trainable"（可训练）两份，小数据集微调不会破坏生产级模型（S7）。在角色一致性语境下，ControlNet 类条件（姿势/深度/线稿/语义分割等）用于把跨段构图、姿势、场景结构钉在可控范围内。【推断其在视频模型的对应实现——视频模型的首尾帧/参考图机制可视为同一思路的产品化，S8】

### 3.4 种子值与参数复现（推断）

- 固定 seed/参数使同一分镜可复现、可对比，是批量生产的标准做法；但视频模型对 seed 的承诺弱于图像模型，主要价值在于 A/B 对比与失败归因。【推断，无官方来源】

### 3.5 段间空间继承（内部规范）

- 内部制作规范（S20）：每段生成前继承"角色站位+道具位置+光源状态"，段末记录空间状态供下一段继承（只继承事实不继承情绪描述）；段级资产锁在代码块首行声明（画幅/风格/负面词 + 角色@图片 + 场景@图片 + 道具@图片 + 音色@音频）。配合 3.2 的平台能力，这是可执行的段间一致性方案。

### 3.6 一致性失败的高发区（实测）

- 多道具与多人战斗场景："双剑的数量变化、水袖的形变、击杀人物反馈不匹配"（S18）；复杂空间动线（第 7 秒前后路径衔接偏差，S18）。对策：缩小镜头任务、多用首尾帧锁定（2.2）。

## 四、声音链路：从分镜声音描述到成片混音

### 4.1 链路总览

分镜声音描述 → 对白配音（TTS/声优）→ 环境声/拟音 → 配乐 → 混音/母带 → 交付。
- 混音定义：把多个声源合并为一个或多个声道，处理音量、频率、动态、声像位置，产出最终听感版本（S6）。
- 电影声音三层结构（内部规范 S20）：对白/VO + 环境声 + 动作音效，音乐仅特殊场景使用；影院声场要求动态范围大（安静更安静、爆发更爆发）、静默是策略。

### 4.2 对白配音（可验证）

- **专业配音（Dubbing）**：ElevenLabs 官方——"用演员原声保留原始表演，翻成任意语言"；v2 全自动；输出格式含 MP4/AAC/**AAF（时间线数据）**/SRT/**WAV（每个说话人独立分轨）**；免费版自动加水印；当前不提供自动对口型（lip sync 需第三方模型）（S13）。
- 传统术语：dubbing 是后期把新对白（常为其他语言）替换原声的过程，lip-synchronisation 现已可由任意音视频输入生成（S4）。
- **模型自带声音**：Seedance 2.0 支持"生成有声视频"（`generate_audio:true`）与音频参考输入（音色跟随）（S8）；MiniMax H3 输出**原生双声道**音视频（S17）。
- 内部规范（S20）：角色音色在段级资产锁中绑定（音色@音频），对白逐字嵌入分镜——台词任何改动会造成全线不一致。

### 4.3 环境声/拟音（可验证+推断）

- Foley（拟音）定义：后期为影片添加的日常音效（衣物摩擦、脚步声、物体碰撞等），由拟音师在录音棚对着画面表演录制（S3）。
- AI 语境【推断】：环境声可来自 ①素材库（现场感音效包）；②AI 音频生成模型按分镜声音描述生成；③视频模型自带的"生成有声视频"（S8）把环境声作为画面物理描述的一部分直接生成（内部规范 S20 即要求音效作为物理描述自然融入提示词）。AI 版拟音的验收标准与传统一致：声画同步、材质真实、层次符合景别（声音透视）。【推断】

### 4.4 配乐（可验证+推断）

- Film score 定义：为影片原创的音乐，由若干"cues"组成，每个 cue 精确对齐影片时间点起止，增强戏剧叙事与情绪冲击；由作曲家与导演/制片人协作完成（S5）。
- AI 配乐【推断】：音乐生成模型（如 Suno 类）按"场景情绪+时长"生成 cues，再进 DAW 对齐时间码；H3 已演示"参考歌声的音频"作为输入模态（S17），说明音色/风格参考是可行的；但 cue 与画面的逐帧对齐仍依赖剪辑时间码（呼应 2.1 的 EDL/AAF 生态）。【推断】

### 4.5 混音与交付（可验证+推断）

- 混音是最终环节：多轨（对白/环境/拟音/配乐）合成、音量平衡、动态与声像处理（S6）。
- 工作流【推断】：AI 生成的分轨素材（如 ElevenLabs 每说话人 WAV 分轨，S13）+ 环境/拟音轨 + 配乐轨 → DAW（Pro Tools/Reaper 等）按 EDL/AAF 时间线混音 → 母带 → 交付。AAF 输出（S13）正是衔接 NLE/DAW 的标准格式。
- 影院声场规范（S20）：动态范围、静默策略、声音透视——混音阶段需按放映环境（影院 vs 流媒体）做不同响度版本。【推断】
