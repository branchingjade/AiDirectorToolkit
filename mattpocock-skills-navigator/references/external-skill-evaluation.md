# 外部技能库评估方法论

当用户要求评估一个外部 skills 仓库时，按以下步骤进行。

## 步骤

1. **读 README** — 了解定位、规模、自称的优势和局限（作者自述的局限尤其重要）
2. **查目录结构** — skills/ 下怎么分层？有没有 scripts/references？CI 是什么水平？
3. **抽样读技能** — 选 3-5 个代表性技能，看实际深度。persona 类看模板是否同质化，workflow 类看方法论是否完整
4. **横向对比** — 和已知基准（mattpocock/skills、用户自有技能、Hermes 内置技能）对比差异
5. **针对用户场景评判** — 不泛泛而谈"好不好"，而是"对你有没有用"

## 常见红色信号

- 数量大但同质化模板 — 958 个技能如果都长一样，实际价值≈零
- 纯角色扮演无执行脚本 — 本质是系统提示词，不是可执行技能
- 自评质量无独立审核 — 分数好看但无外部验证
- 描述重叠 — 很多技能 description 几乎一样，自动发现时互相干扰
- workflow 是别人的简化版 — 标了 inspired_by 但砍掉了方法论支撑体系

## 评估示例

本次对 `theneoai/awesome-skills` 的评估：956 个技能、自评质量分、企业方法论亮点、但深度有限。对当前用户的价值：★☆☆（作为灵感目录翻翻可以，实际生产力远不如自有技能体系）。
