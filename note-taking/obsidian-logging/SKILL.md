# Obsidian 日志维护

> 日志不是文件列表，是知识库的记忆系统。

## 目录架构

```
日志/
├── 2026-06/                          ← 年月目录做第一层分组
│   └── W4/
│       └── 2026-06-24~25.md
│
└── 2026-07/
    ├── 2026-07-月报.md                ← 月报=索引（一文件双职）
    ├── 2026-07-W2-周报.md             ← 周报
    ├── 2026-07-W3-周报.md
    ├── 2026-07-W4-周报.md
    ├── W2/                            ← 周号按月重置，空周不建目录
    │   ├── 2026-07-07.md
    │   ├── 2026-07-08.md
    │   ├── 2026-07-09.md
    │   └── 2026-07-10.md
    ├── W3/
    │   ├── 2026-07-15.md
    │   ├── 2026-07-17.md
    │   └── 2026-07-20.md
    └── W4/
        └── 2026-07-21.md
```

**规则：**
- 年月目录做第一层分组（12个/年，可管理）
- 周号按月重置（每月从W1开始），空周不建目录
- 周报紧贴月目录，不另建子目录
- 月报充当该月索引（一文件双职：索引+总结，不另建README/索引文件）

## 命名规范

| 类型 | 格式 | 示例 |
|------|------|------|
| 日报 | `YYYY-MM-DD.md` | `2026-07-21.md` |
| 周报 | `YYYY-MM-W{N}-周报.md` | `2026-07-W2-周报.md` |
| 月报 | `YYYY-MM-月报.md` | `2026-07-月报.md` |

- **全日期命名**：文件名自描述，离开目录仍可搜索识别
- **统一 `-` 分隔**：不用 `_` `~` 混搭
- **不用 README.md**：Obsidian不渲染README，月报本身就是索引

## 月报索引

一页讲清本月全貌。**必须包含：**

1. **本月主题**（2-3个核心主题）
2. **各周日志表**（日期 \| 做了什么 \| 结果）
3. **跨日关联**（识别同根因的模式，如07-20和07-21都爆发"不读文档"）
4. **关键决策**（改了什么、为什么、影响）
5. **产出清单**（代码/配置/文档/设计）
6. **遗留/待办**（开了头没做完的事）
7. **本月教训**（最重要的1-3条）

**梗概格式：** `任务主题 — 具体做了什么+结果`

❌ `对 GitHub 仓库做了完整品鉴`（没说什么仓库，没说什么结果）
✅ `AiDirectorToolkit品鉴 — 发现6个问题（版本号bug、校验脚本硬编码、约束重复），制定修复计划`

### 梗概铁律

**禁止截首行作为梗概。** 必须写清楚任务主题+结果，手工撰写，不从正文首行截取。

## 日报内容标准

3个月后翻到这天要能看懂发生了什么。每个实质性会话日必须包含：
- 任务主题和具体操作
- 结果/产出
- 踩的坑和教训
- 关联的project文档（放在 `related:` 字段）

❌ **骨架日报（禁止）：**
```md
- 品鉴AiDirectorToolkit
- 发现6个问题
```

✅ **实质日报：**
```md
## AiDirectorToolkit 品鉴
对 GitHub 仓库 branchingjade/AiDirectorToolkit 做了完整品鉴。
### 架构设计 ★★★★★
三层 Skill 架构：AI短剧编剧助手→AI短剧导演助手→交付…
### 发现6个问题
| 1 | 版本号v1.1.0→v1.2.1 | SKILL.md:171 |
```

## 反孤岛规则

每篇日志必须有 `related` 字段：
- **日报** → 链周报 + 月报 + 关联项目文档
- **周报** → 链月报 + 本月日报
- **月报** → 链本月周报 + 跨月项目文档（如 `[[网页抓取任务复盘]]`）

图谱中不应有入链或出链为0的日志节点。

## 触发时机

- **每日**：有产出/决策/踩坑就写。无内容的日子不写空文件
- **每周**：总结本周产出和教训
- **每月**：汇总主题、决策、教训 → 生成月报

## 与 knowledge-base skill 的关系

knowledge-base skill 定义知识库总体架构和维护流程。本 skill 补充日志模块的具体规范。日志的frontmatter、git流程遵循 knowledge-base skill。

## Pitfalls

### 骨架日报
用户对空洞日志零容忍。无内容直接删文件，不保留空壳。

### README.md在Obsidian不渲染
Obsidian不把README.md当作特殊首页。月报本身就是索引，不另建README。

### 梗概截首行
自动截取正文第一行会导致模糊描述。必须手工写"任务主题 — 结果"格式。

### 另建索引文件

**严禁**在月报之外另建 `索引.md` 或 `README.md`。月报本身就是索引——合并后少一个文件，多一份聚焦。这个决定经过了名→结构→内容三轮迭代最终确认。
