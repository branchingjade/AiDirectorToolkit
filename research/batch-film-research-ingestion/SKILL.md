# 批量电影研习 + 知识库入库轮次流程

## 适用场景

妖玉影视知识库的持续建设轮次：导演美学深化（3-4 导演 × 2 作品 + 1 手法体系深化 = 9-12 子代理）、**大波次扩建**（6 导演×3 + 5 密码回测 + 6 补充作品 = 29 子代理单波，2026-08-07 实测 23 分钟完成，并行度不降质）、**补充作品轮**（已深化导演的未研习单片，1 子代理/片只产研习报告+技法卡片）、题材密码提炼（多套并行）、题材密码实战回测（真实/虚构项目）、场景检索表/招式速查升级。用户以「继续/继续沉淀」驱动轮次推进；**用户要求扩量时先出「名单+规划+可行性和收益判断」**（2026-08-07 用户原话「这轮直接多跑些，你出名单和规划，判断可行性和收益」→「可以再多吗」→「既然可行，那就节省时间，再出名单」——出规划→确认→单波全开三步节奏），每轮走完整流程后同步 GitHub 正本打 tag。

## 知识库三层结构（进化模型）

- **塔基**：大师技法卡片（按片，三读法）
- **塔身**：题材密码（按题材）+ 核心招式速查 + 场景检索表（提炼层）
- **验证**：实战回测报告（真实项目优先，虚构项目兜底）

节奏判断：塔基够厚但塔身滞后 → 补提炼层（题材密码/招式速查）；提炼层闭环 → 继续铺塔基（新增导演/范本）。「导演深化是研究，题材密码才是创作时真正查的东西」——提炼层优先。

## 标准轮次流程

1. **盘存量**：批派前查知识库已有卡片/导演/作品，避免重复研习（`ls references/大师技法卡片 | grep` 候选作品）；查 pages/ 存量存档——子代理优先复用存量、零新抓
2. **批派子代理**：9-12 个 leaf（deepseek-v4-flash），每子代理 context 必含：产出文件绝对路径（写死防覆盖）、第一步盘存量、重点观察方向、质量纪律（引文 grep 0 MISS、预设待验证证伪即改、诚实声明未取证项）、输出语言。选导演逻辑：创作参照系 + 知识缺口 + 已有作品卡片做转引链。**扩量时（用户「多跑些」）**：先出三块名单——密码回测补闭环（5 子代理）+ 新导演×3 模式（6 导演=18 子代理）+ 已深化导演补充作品（6 子代理=29 波），给每导演选人理由（缺口/对照系/喂创作）和收益排序，可行性判断（系统上限 100 无压力、单波 29 约 23 分钟比两波省一半），用户确认后单波全开。**补充作品轮**：1 子代理/片（研习报告+技法卡片），context 强调转引该导演深化文档对照。
3. **验证落盘**：子代理自报不可信——以文件系统为准（ls -la 检查每个交付物存在 + 大小）
4. **入库**：技法卡片→知识库 `references/大师技法卡片/`；手法体系深化→`references/导演美学卡片/`；研习报告→Obsidian 剧本库（华语/海外分库，按片源语言）
5. **SKILL.md 更新**：description（计数）、层3/层4 描述、导演索引表/题材密码索引表、version 递增
6. **全量自检**：MOC 链接数=磁盘数；招式速查数据行数=声明数；description 关键数字 grep
7. **GitHub 同步**：cp SKILL.md + references 到正本 → git add -A → commit → tag kb-vX.Y.Z → `git push origin master --tags`（正本分支是 **master** 不是 main）

## 子代理 context 模板要点（导演研习轮）

```
你是<导演>深化研习子代理。技能 director-aesthetic-card 已内置指导。
【产出文件】（写死，勿改路径）
- 研习报告: .../研习报告/<片名>_研习报告.md
- 技法卡片: .../技法卡片源稿/<片名>_技法卡片.md
【第一步·盘存量】cd 到 .../pages 查相关存档（<prefix>_*），先复用存量再新抓
【重点】①创作路线归类（跨作品矩阵）②手法演变链（逐阶段带证据）
③泛用工具箱（5件以上：每件=适用场景+AI提示词，标注"按取证要点编写，非原片描述"）
④vs <对比导演>（经本地深化文档转引链，不重复研习已有作品）
【质量纪律】①引文必须 grep 校验 0 MISS ②任务预设一律待验证，证伪即改
③诚实声明未取证项 ④输出中文
```

## 题材密码实战回测闭环（子流程）

触发：题材密码 v1.0 建完后用户说「先测/继续测」。

1. **选项目**：真实项目优先（手心人测了科幻奇幻+都市情感两套）；真实项目池耗尽后用虚构项目——年夜饭→家庭、码头的秩序→犯罪、盐道→历史、第七梦→梦境、网吧岁月→底层、白夜理发店→悬疑、倒霉剧组→喜剧、断刀门→武侠动作、雨季不再来→爱情、渡口→剧情作者（每套密码一个虚构项目；**13 套密码全部回测闭环于 2026-08-07 第二十轮**）
2. **子代理产出回测报告**（独立落盘 `回测报告/`，**不直接改密码文档**——主线程统一回写防并发冲突）：造项目设计（一句话故事+结构+6-8 关键场次带动作/对白落点）→ 逐节对照密码（定义谱系/世界观规则/结构范式/调性/常见坑/自检清单）→ 命中/缺口/证伪三清单（带密码章节引用+虚构场次证据）→ 可用性评级（✅🟡🔴）+ 最值得回写 3 条
3. **主线程回写密码**：v1.0→v1.1（早期密码 v0.3/v0.4 → v0.4/v0.5，**按各自版本号递增**，版本行注明「回测新增/回测修正」+ 回测项目名），正文按「最值得回写 3 条」精确 patch（注意引号转义、patch 插错位置会复制标题行——写完 grep 检查章节唯一性）；自检清单补对应条目。回写内容=新范式/新亚型（如错位审讯范式八、一本正经的倒霉、命运引擎、告别型爱情、串珠变奏双型）+ 修正（层3定位、载体泛化）+ 版本行。
4. **归档**：回测报告 cp 到知识库 `references/实战回测/`
5. **SKILL.md 索引**：题材密码索引表状态列 v1.0→v1.1 并注回测来源

## 坑位清单（实测，多轮验证）

1. **tag 冲突**：版本号必须单调递增且每次 commit 前 `git tag | tail -5` 检查；tag 已存在 → push 整体 fatal（本地 commit 已生成但远端未推），须改 version 后重新 commit+tag+push。实测 kb-v1.11.0 被前一轮占用，本轮应为 1.12.0。
2. **子代理改共享 SKILL.md**：批派轮子代理可能修改 SKILL.md（sibling modification warning）；覆盖前必须 re-read + 程序化数实际行数（execute_code 数 `| **` 数据行）。曾把 51 条速查误改回 48 条、丢掉子代理新增的「+3 条伏妖记实战验证」标注——先数数据行再写 description 和声明。
3. **编号冲突**：并行子代理各自分配共享编号空间（题材库 02/05/07 重复）→ 父线程统一 01-13；批派时若共享编号空间应预分配唯一号。
4. **子代理超时≠成果丢失**：工具轮次耗尽但素材已落盘 pages/ → 派补写轮（新子代理，context 给存档清单+前轮核心发现+质量纪律）直接撰写文档，引文校验后入库。未麻的部屋案例：首轮 19 存档 + 补写轮 256 引文 0 MISS。判定补写前先查交付物是否已落盘（子代理可能超时前已写完）。
5. **description 误删尾部段**：patch description 时 old_string 不含末尾段（如「工具参考（Seedance 2.5 官方理解）」）会导致被删——写入前读全文。
6. **正本漏同步**：本地 skill 与 GitHub 正本双份，cp 漏 SKILL.md 会滞后（曾漏同步检索表 43 行改动，补 commit）。cp 后用 md5sum 对比本地 vs 正本。
7. **MOC 计数漂移**：头部「配套」行、库结构行、小节计数（`### 研习报告（N 份）`）三处都要改；自检用 MOC 链接数=磁盘数（正则 `[[华语剧本/研习报告/` 计数 vs 目录文件数）。**MOC 可能被子代理/并行会话改过**（sibling modification warning 也出现在 MOC 上）——patch 前 re-read，且新增链接行的 old_string 用「上一行+本行+下一行」三行锚定（单行在 MOC 里几乎必撞车，实测 4-5 个匹配）。
8. **引文校验纪律**：子代理必须 grep 0 MISS；「任务预设待验证」是硬纪律——多轮出现预设纠正（Criterion essay 作者 Frank Rich 非 MacCabe、Ebert 四星制、「You talkin' to me?」剧本没有=德尼罗即兴、鬼片尾曲证伪、画皮1966=鲍方非李翰祥、梁家辉饰咸丰非慈禧、角斗士「20 分钟开场」实为 10 分钟）。繁简映射/弯引号/未闭合 `<ref>`/维基模板剥壳是假 MISS 高频源。
9. **泛用铁律**：研习产出的「可复用工具箱」必须写泛用手法（按创作场景归类），禁止「对接 XX 项目」定向表述——知识库是土壤层服务所有创作（用户 2026-08-07 纠正）。
10. **繁简转换用 opencc 而非手写映射表**：手写繁简映射表遇 兒/個 等异码与缺字会 ValueError 或假 MISS；`zhconv` 或 `opencc`（python -m pip 装）t2s 全量转换一次到位。霸王别姬轮案例。
11. **维基 raw 的 cite web 模板 `quote=` 参数**：引文藏在模板参数里，剥模板前必须提取拼回，否则引文被吞（火烧圆明园轮新坑）。同理未闭合 `<ref>` 吞正文——先剥自闭合再剥成对，raw 压空白兜底。
12. **wayback 老中文页 GBK 编码**：老页面按字节解码（GBK→utf-8），否则乱码假 MISS。
13. **execute_code/terminal cwd 陷阱**：子代理跑 execute_code 时工作目录不在 pages/，脚本用相对路径写文件会落 Hermes 根目录（谢晋轮 24 篇长评误落根目录已迁移）——写文件一律绝对路径；校验脚本存 pages/ 或源稿目录。
14. **「SKILL.md 100K 上限」是误诊——真正机制是上下文压缩剪裁（2026-08-07 第二十轮查证，修正旧版条目）**：官方文档确认 **Hermes 对 skill 文件大小没有硬上限**（196KB 的 SKILL.md 能正常加载）。子代理报「SKILL.md 已达 100K 上限」时，真实情况是：`[SKILL_PRUNED]` = **上下文压缩时对超大 skill 内容的剪裁**（skill 内容进上下文有预算，超出部分被压缩掉→子代理看不到完整指导），不是文件被拒绝。**排查步骤**：①`wc -c <SKILL.md>` 实测文件大小（知识库 SKILL.md 实测仅 31.8KB，完全健康，根本不用拆）；②子代理说指导不完整时，查**它们真正加载的 skill**（研习子代理加载的是 director-aesthetic-card 而非知识库）——196KB 的 director-aesthetic-card 才是被剪裁的元凶；③诊断超长文件：`awk '{print length($0), NR}' | sort -rn | head` 找单行巨型 blob（196KB/237 行 = 平均 800+ 字符/行，实测有 15KB/7.6KB/6KB 的超长行）；④看「参考」章节是否冗余登记 references 文件（linked_files 会自动列出全部 references，正文手动登记 119 个来源地图是纯冗余~55KB）。**正确修法（结构手术而非拆分）**：核心指导留在 SKILL.md 正文（瘦身后 ~40KB），坑记录移 references/pitfalls-log.md（按需加载），冗余的来源地图登记行删除（linked_files 自动列出），轮次实测长文压缩成一句话摘要。知识库 SKILL.md 31.8KB 健康——**以后子代理再报「100K 上限」，先实测大小再决定动不动手**。
15. **引文校验三明治法（0 MISS 门禁实操，蓝丝绒补写轮实测）**：三层校验——①短语级抽查（挑 20-100 条关键引文核心短语 grep 对应存档）；②全文档提取级（正则提取引号内片段：英文 `"..."`≥25 字符、中文「」≥15 字符，对 pages/ 语料做滑动窗口匹配：英文 4 词窗口、中文 12 字符窗口，先压空白/小写/去弯引号——容忍 wiki 标记 `[[..]]`/斜体/`&nbsp;` 打断短语）；③**MISS 分类先行再修**：译文（对应英文原文已 PASS 即正常，不修）、AI 提示词示例（创作建议非引文，不修）、维基标记假 MISS（换更短短语复核）、真错（才改稿）。蓝丝绒轮实测：95 条抽查 17 MISS 全为 wiki 标记假 MISS；全量提取 78 条、51 个疑似 MISS 分类后仅 3 个真错。真错案例：①Ebert 原文是 `"Mulholland Drive" is all dream`（非 The movie is all dream）；②中维引文简繁混用——「说，蓝丝绒是当年他最喜歡的电影」混简繁，应原样繁体「說，藍絲絨是當年他最喜歡的電影」（引 zhwiki 繁体原文禁止手写简繁混合，要么原样繁体要么 opencc 全量转换）；③转述引文应补原文（Kite 的 Upanishad 蜘蛛引文 we are like the dreamer who dreams and then lives in the dream）。校验脚本见 scripts/verify_quotes.py（可直接复用）。
