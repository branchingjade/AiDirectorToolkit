# 飞书评论创作润色工作流

> **加载机制（2026-08-31，2026-09-04 修订）**：本 skill 不通过 `enabled_toolsets` 或 `skills=` 参数加载——AIAgent 暂无 `skills=` 参数。`feishu_comment.py::_run_creative_agent()` 在运行时把 SKILL.md 全文（前导 YAML 已剥离）作为 `system_message` 参数传给 `AIAgent.run_conversation`。改这个文件下次触发立即生效，不需要重启 skill 索引。⚠️ **不要传 `prefill_messages` 参数**——AIAgent.run_conversation 不支持（2026-09-03 实战踩坑），必须用 `system_message=` 传 system 内容。

## When to Use

飞书文档评论中出现「润色/改/优化/重写/调整/做出合理改动」时触发。不等用户追问，直接输出完整方案。

触发检测在 `feishu_comment.py::_detect_creative_intent()`，关键词清单（共16 组）：润色、打磨、重写、改.{0,6}(这场|这段|这句|这场戏|对白|台词)、优化.{0,6}(对白|台词|剧本|场景|分镜|画面|动作)、(调整|改).{0,4}(节奏|结构|人物|口吻|情绪|语气)、做出合理改动、(补|加).{0,4}(一句|一段|几场|场戏)、(改写|改写为|改写成)、换个写法、(试试|换一个).{0,6}(写法|版本|方案|路子)、(再来|重做).{0,6}(一版|一下|一次)、(怎么写|怎么改|怎么调)、(更好|更紧凑|更利落|更准|更狠|更冷|更顺).{0,4}(点|些|一点|一些)?、(再|更).{0,6}(紧|慢|狠|准|冷|利落|紧凑|克制|激烈).{0,6}(点|些|一点|一些)?、(节奏|人物|口吻|语气).{0,6}(更|再|要).{0,6}(紧|狠|准|冷|克制|激烈|稳|硬)。

## 工作流

### 1. 读全文（不只读引用段）

用 `feishu_doc_read` 读完整场景，理解：
- 这场戏的**叙事功能**是什么（建立人物/推动情节/制造反差/收束情感）
- 引用段在整场戏里的**位置和作用**
- 前后场的**衔接关系**

### 2. 三关审查

| 关 | 问题 | 产出 |
|---|---|---|
| **合理性** | 逻辑漏洞？角色行为贴人设？ | 修复项 |
| **精彩度** | 够不够好？有没有「该更精彩但没做」的？ | 强化项 |
| **可能性** | 还有没有别的做法？当前方案是不是最优？ | 备选方案 |

### 3. 给多个完整方案（不是碎片建议）

**必须给 2-3 个完整润色版**，每个方案是可直接使用的完整文本，不是「把 X 改成 Y」的 bullet point。

每个方案包含：
- 核心思路（一句话）
- 完整润色后的文本（可直接复制使用）
- 改动说明（改了什么、为什么改）

### 4. 对比表

结尾附对比表：

| | 方案 A | 方案 B | 方案 C |
|---|---|---|---|
| 核心思路 | ... | ... | ... |
| 改动量 | 小/中/大 | ... | ... |
| 节奏 | 快/中/冷 | ... | ... |
| 适合什么调子 | ... | ... | ... |

### 5. 输出格式（电影剧本格式，2026-09-04 拍板）

**必须用电影剧本格式输出**——按知识库《国内标准剧本格式行业规范带跟脚》（`viking://resources/skills/yaoyu-film/AI电影编剧.md/AI电影编剧_v2.14.3/四国内标准剧本格式行业规范带跟脚/`）执行。

**场次标题**：`第N场 地点 空间细节 时间 内外`（中文自然语言，不用 INT./EXT./全大写）
- 范例：`第8场 民舍 门外 日 外`（《大明劫》用"第8场"），`1. 剧院 日 内`（《霸王别姬》用"1."）

**动作描述**：
- 现在时态，只写现在发生的事
- 只写可见可听之物，情绪靠行为不靠内心独白
- 段首空两格（word 交付），markdown 交付用空行分段亦可
- 不标"切镜头"等导演术语——电影剧本正文不写镜号
- 国产片不标转场，场与场直接衔接

**对白**：`角色名：（状态）台词`，**不加引号**
- 状态提示用括号，位置两种都合法：人名后（`格拉斯（轻声）：还不行……`）或冒号后（`贾晓玲：（心虚）几千，好几百份吧。`），全剧保持一致
- 连续性对白用多重括号：`化雨（对婶婶）：没事。（对方可可）刚才没发现……`
- 拟声词裸写不加引号：`噗……扎进了他的后脖颈`
- 首出场可带年龄/外形：`陆青山（20岁，身形偏瘦）`

**画外音**：`画外音：内容`（中文标注，不用 O.S./V.O.）

**闪回**：`【闪回】地点 时间 内外`，返回用"闪回结束"

**输出模板**：

```
第1场 某地 空间 日 外

陆青山（20岁，身形偏瘦）走在芦苇荡里，剑匣搁在脚边。

　　他停下，望向远处。

小白（18岁，清瘦）坐在石头上，下巴抵在膝盖上，看水里自己的倒影。

陆青山 走。

（对比表用纯文本，不 markdown）

|  | 方案 A | 方案 B | 方案 C |
|---|---|---|---|
| 核心思路 | ... | ... | ... |
| 改动量 | 小 | 中 | 大 |
```

**禁用**：镜号、△ 切镜头（短剧格式，**电影不要**）、代码块、修改说明、Markdown 标题/列表/MD 表格（对比表用纯文本）

- 不要只给建议，要给完整文本
- 不要等用户追问，直接输出完整方案
- 段落开头标注一次即可，不要逐句重复标注

## 创作原则（从知识库提取）

### 武侠/动作场景
- **差异化阶梯**（新龙门客栈）：一人一武器一性格，动作即身份证
- **剪辑造武打**（侠女）：短镜头跳切替代套招，用「结果」代替「过程」
- **以静制动**：顶尖高手不追不赶，等对方露出破绽
- **动作暴露人物**：打斗必须服务人物弧光，不是为打而打

### 对白/人物
- 动词要短要脆：「猛地发力」→「脚尖一点」
- 用角色自己的声音：毒、冷、平、带骨气
- 师徒/强弱对比用交叉剪辑或时间差，不用对白解释
- 不要用「心神一凛」「猛然发力」这类泛化动作词——每个动词要贴角色身份

### 节奏
- 战斗激烈，收尾要轻（随手抛回伏妖袋，头也不回往前走）
- 喜剧调节阀在连续高压段必须存在
- 信息差：角色不知道的，观众知道，留给观众自己连接

## Pitfalls

- **不要只改引用段**——用户说「润色」是整体上改剧本，不是改几个词
- **不要只给建议**——用户要的是完整可用的文本，不是 bullet point
- **不要只给一个方案**——至少给 2 个，让用户有选择
- **不要等用户追问**——直接输出完整方案，不要问「你倾向哪个方向」
- **读全文再动手**——不读完整场景就改，容易改出逻辑漏洞

## 子代理派工做创作类润色（v7→v8 实战教训，2026-09-09）

**触发**：当润色工作量超出单次回复（66 场长剧本、5+ 段重写）需要派 6 批子代理并行打磨时。

**根因教训**：v7 派 6 批子代理只说"逐场润色"——子代理按"通用 LLM 理解"做最低标准的机械清理（删 AI 词+修笔误+修标点），**没拿到"创作类 skill"**，输出停留在表层。**用户多次反馈"润色幅度不够/没达到我要求的每一场"**。

**强制加载清单**（派工 prompt 必须包含）：

```python
【强制加载的 skill】（这次必须加载，v7/v8 子代理没加载是问题根因）：

   level=full  （志怪题材核心密码：三界规则/六步结构/四范本/三调混搭/自检清单）

   level=full  （逐场创作打磨：人物塑造/类型惯例/对白体系/序列设计）

   level=overview （场次标题/动作/对白/画外音 规范）
4. 可选加载（同类范本对照）：
   - 大师技法卡片/倩女幽魂_技法卡片.md
```

**派工深度对比**：

| 派工 prompt | 子代理输出 | 用户反应 |
|------------|------------|----------|
| 「逐场润色」 | 机械清理（AI 词+笔误+标点） | "润色幅度不够" |
| 「v8 创作类深度：贴人物声音+改对白+改动作质感+改节奏+去评述腔」+强制 skill 加载 | 真创作打磨（对白贴角色+动作质感+评述腔+规则进战术层） | 终稿接受 |

**子代理输出文件结构**（v7 错版教训）：

- ✅ 输出：正文写 `scenes_v9/*.md`（只含标题+段落）；审计写 `audit_batch{N}_v9.md`（独立文件）
- ❌ 不要把"改动审计（A/B/C/D/E/F/G 五维度分析）"写进 .md 正文文件后面——合并时字符暴涨 37%（v7 46276 vs K5d3 33731=+12545 元信息）

**合并时清理**（避免元信息膨胀）：

```python
content = re.sub(r'^##\s*[^\n]*\n', '', content, flags=re.MULTILINE)  # 删 ## 标题
content = re.sub(r'^---\s*\n', '', content, flags=re.MULTILINE)  # 删 --- 分隔
for letter in 'ABCDEFG':
    content = re.sub(rf'\*\*{letter}\.[\s\S]*?(?=\n\n|\Z)', '', content)  # 删 A. B. 审计段
# 验证：合并后总字符应 < 源文档 + 少量改动（< 5000 字符）
```

**判据**：v7 合并后 46276 字符（K5d3 原文 + 12545 元信息=37% 膨胀）= 必有问题。v8/v9 修正后 32047 字符（K5d3 原文 - 1684 改动=正常）。
