# 导演美学卡片（Director Aesthetic Card）v1.0.0

## 定位

与用户套件「电影大师研习」（读剧本 → 技法卡片）互补：本技能负责**导演层取证**——不写泛泛手法清单，只写"从电影本体和导演自己说的话里看到的"。产出《导演美学卡片》或《手法体系深化》专题，存档到 `film-suite-research/技法卡片源稿/<导演>_导演美学卡片.md`（变体见下节）。


**历轮实测记录（2026-08 三十余轮）已归档：`references/rounds-log.md`**——每轮详情仍见对应的 `references/<轮次>-study-2026-08.md` 地图文件；正文引用以地图文件为准。


## 适用

- 为知识库深挖某位大师导演（黑泽明/贾樟柯/王家卫/诺兰/科恩兄弟…）的视觉美学
- 已有维基二手理论，需要一手证据（成片表现+访谈+幕后）补强
- 产出对接 AI 分镜/提示词套件（Seedance 等）

## 工作流（按序执行）

0. **⚠️ 先加载坑库（必做，第 0 步）**：`skill_view(name='director-aesthetic-card', file_path='references/pitfalls-log.md')`——40+ 编号坑（㉟㊱㊲…㊿-轮次）是三十余轮实测的血泪教训，写卡前先扫一遍，命中同类场景（豆瓣通道/wayback/Ebert/繁简/引文校验）即避坑，不看会重蹈覆辙。

1. **先盘 pages/ 存量存档，再读本库资产，最后才抓新**（胡金铨第八轮：40+ 个 `kinghu_*.txt/.json` 存量覆盖了 80% 证据，仅补抓 4 个新源）：
   - `ls pages/ | grep <导演前缀>` 列出全部存量；用脚本批量打印每个文件的前 200 字符头 + 字节数，一次建出"存档地图"（谁是什么内容），再按需深读。
   - 存档命名规律：`<前缀>_wiki_<片名>.txt`（中文维基，**含大量 CSS 噪音，先 `re.sub(r'<[^>]+>','')` + 压空白再 grep**）、`<前缀>_wikipedia_en/zh.txt`（主条目）、`<前缀>_baike*.txt`（百度百科经 jina）、`<前缀>_review_<ID>.txt`（豆瓣影评）、`<前缀>_rexxar*.json`（豆瓣短评 JSON，`json.load` 后取 interests[].comment，干净可批量过滤关键词）。
   - **⚠️ pinyin 前缀跨片碰撞（英雄轮 2026-08 实测，险些污染整份报告）**：`yingxiong_*` 前缀的 11 篇豆瓣长评 + baike + imsdb 存档**全部属于《英雄本色》(1986, 吴宇森) 而非《英雄》(2002, 张艺谋)**——同 pinyin 前缀被不同片轮重复使用，`ls | grep` 命中不等于内容匹配。复用前**核对 subject id / 正文首行标题**（本片是 subject 1306123 的评论），新轮存档用能区分片的命名（本片用 `hero2002_*`，导演轮 `yimou_*`）。
   - **并行研习轮共享 pages/，中途会新增存档（聂隐娘轮 2026-08 实测）**：任务断言"零存量"且开局 `ls | grep` 确为空，但抓取中途出现 30+ 个 `hou_beiqing_*`（悲情城市并行轮的侯孝贤存档：SoC 导演专条/Criterion essay/13 篇长评）——**抓新前与写卡片前各重扫一次导演级前缀**（`ls pages | grep <导演拼音>`，用导演名而非片名；贾樟柯轮 jia_*/platform_* 并存同理），发现的跨片导演存量中途复用；复用前仍按 pinyin 碰撞规则核对内容归属。**同批并行轮产出未落盘时的 [卡X] 登记（小津轮 2026-08 实测）**：并行子代理的技法卡片/研习报告尚未落盘、但 pages/ 已出现其新抓存档（ozu_tokyo_baike_jina.txt / ozu_tokyo_zhwiki_raw.txt 等，含中文维基与百科的片条目）时——深化文档直接以这些存档为证据，按「主卡片表外存档」用 [卡X] 前缀登记进附录（[卡D]-[卡G]），并在诚实声明注明「同批产物写作时未落盘，跨片证据直接取自 pages/ 存档，若稍后落盘可互引」；新存档同样按歧义词条规则核对内容归属（小津轮 [卡F]「晚春」百科即此轮并行新增、实为韩愈诗）。
   - **导演美学卡片文末「附录：取证来源清单」= 原始存档索引（英雄轮实测）**：做单部片研习时先读 `<导演>_导演美学卡片.md` 附录表（文件名↔来源↔关键内容），按表直接定位并 grep 原始存档（如新浪访谈「黑色宫殿」段在 yimou_sina_bigred.txt），引文对原始存档核验，不必重抓。
   - **单片轮先按片名 grep 主卡片的「访谈/长文」类来源（星际穿越轮 2026-08 实测）**：主卡片标为访谈/长文的存档（如 nolan_guardian2014_wb.txt = Guardian Tom Shone 2014 长文）常含该片的英文一手金矿——《星际穿越》的 1h=7y 英文原句、海瑟薇「calm certainty」表演指导原话、Flora's Letter 工作名全在其中，密度高于中文渠道；写报告前先 `grep <片名>` 导演级访谈存档，命中即复用并标注 [卡S#]，别只依赖新抓中文源。顺带可闭环深化轮遗留的「未逐字取证」项（诺兰深化轮称 1h=7y 不在维基存档，本轮在 Guardian 访谈原句+豆瓣解析+百科简介三处补齐）。英维 raw 存量用 `tail -c` 查文末 categories 确认完整后再决定是否重抓；**新抓与存量字节数完全一致=同文免重复分析（盗梦空间轮实测 143513==143513），登记「同源复核」直接复用存量即可**。
   - 然后读 `技法卡片源稿/<相关片>_技法卡片.md`、`剧本原文/`、`研习报告/`——剧本级证据（场次/行号）直接复用。黑泽明案例：七武士/乱/罗生门三张技法卡片本身就是桥段拆解的主力证据。
2. **Wikipedia wikitext 取证**（一手制作事实 + 转引链）：`curl -L "https://en.wikipedia.org/w/index.php?title=<T>&action=raw"` → 可 grep 的 wikitext，引用 ref/sfn 保留。重点挖：production 段（多机位/镜头数/实拍条件/拍摄天数/演员受伤）、主题段（影评人/学者的概括句）、**ref 里的 archive-url 字段 = 死链文章的快照入口**。
   - 坑：带括号标题需 `%28` `%29` 编码；`X (film)` 可能是重定向（Rashomon (film)→Rashomon）；action=raw 偶发 Wikimedia Error → 换 `api/rest_v1/page/html/<T>`，或先 `action=query&list=search&srsearch=<词>` 找真实条目名。
   - **rest_v1 返回 `MediaWikiError/Not_Found`（rest-nonexistent-title）≠ 条目不存在，是标题猜错**：英文电影条目常不带年份消歧——《刀》真实标题是 `The Blade (film)`，猜 `The Blade (1995 film)` 会 404。解法：`action=query&list=search&srsearch=<片名+导演>&srlimit=5` 拿真实标题再抓（徐克轮实测一次搜索同时解决两个条目）。**`api/rest_v1/page/plaintext/<T>` 批量 404 时（黑泽明轮：Throne of Blood/Yojimbo (film)/Sanjuro 全挂）**改用 `action=query&prop=extracts&explaintext=1&format=json&titles=<T1>%7C<T2>&redirects=1`——⚠️ 多标题请求里缺失/重定向条目 extract 为空（实测三标题只回 Sanjuro），**逐条单查最稳**。
   - **Senses of Cinema Great Directors 条目 slug 不规则**：`/2003/great-directors/tsui_hark/` 404，真实 URL 是 `.../great-directors/tsui/`——别按 firstname-lastname 猜；用站点搜索 `https://www.sensesofcinema.com/?s=<导演名>` + grep HTML 里的文章 URL 一步定位（徐克轮实测；该文作者 Grady Hendrix 与 Film Comment 注释版同人，可互补引用）。**文章作者也从站内搜索页拿（悲情城市轮实测）**：jina 渲染的文章正文常无署名行——`?s=<导演名>` 搜索结果的标题下方即作者+日期（Fergus Daly, February 2001），引用署名以此为准。
   - **有 `Cinematic style of <导演>` 专条的先抓专条**（诺兰轮：141KB wikitext，含一手 quote box、学者分析、VFX/时间线硬数据，信息密度高于主条目，详见 playbook §1）
3. **Wayback 补死链/被墙源**：
   - 死链：直接用维基 ref 里的 `archive-url`（Criterion 旧文案例：`criterion.com/current/posts/196` 已死 → `web.archive.org/web/20101128061133/http://www.criterion.com/current/posts/196-...` 秒回全文）。
   - 被 Cloudflare 挡的站（rogerebert.com）：CDX API 发现存档 slug → 抓快照（配方见 references/source-mining-playbook.md）。
   - ⚠️ CDX 通配查询会 403：`url=域名/路径*` 这类带通配符的查询（2026-08 实测 `theguardian.com/film/2016/feb/*`）无授权直接返回 403 "requires authorization"；需要先发现 slug 时，改从维基词条 References 段的 href 里挖 URL，再用精确 URL 抓。**例外（大红灯笼轮 2026-08 实测）：短而精确的路径前缀通配可用**——`url=rogerebert.com/reviews/raise-the-red-lantern*`（不带 matchType 参数，仅 url 尾部 `*`）直接返回 2013-2016 快照列表，一次定位 Ebert 老影评真实 slug `raise-the-red-lantern-1992`（猜的 great-movie-raise-the-red-lantern-1991 是 404；wayback available API 当时 429 限流，CDX 无碍）。403 多半出在域名级/长路径通配；短 slug 前缀值得先试一发。
   - Ebert Great Movies 的 slug 规律：`great-movie-<标题>-<年份>`（如 `great-movie-the-seven-samurai-1954`）；裸 slug（`/reviews/seven-samurai-1954`）是 404。
   - **Ebert wayback 正文提取别用正文中段锚点（用心棒轮 2026-08 实测）**：`t.find('So opens')` 起手会截掉开场段——Ebert 的开场段（"Almost the first thing the samurai sees..."，含狗叼断手关键证据）在正文真正开头，从 **meta description 的首句**（`<meta content="Almost the first thing..."`）起找正文起点，`<p>` 逐段提取到 `Cast and crew` 止，20 段/8.4KB 全量。**Ebert 快照无 meta description、无 post-content class 时的 h1+角色名定位法（晚春轮 2026-08 实测）**：69KB wayback 快照既无 meta description 也无 post-content，meganav 下拉菜单的 `<p>` 摘录（如别的电影评语「The movie is such a gabfest…」=Non-Fiction 2019 摘录）混进正文提取——解法：找 `<h1>`（片名「Late Spring」）→ 从其后第一个提到角色名/导演名的 `<p>`（如「Shukichi is a professor, a widower…」）为正文起点 → 按 `Comments|More Great Movies|Cast and crew` 截尾 → 20 段 8714 字符干净到手；中段 `<p>` 命中测试不可靠（会命中导航摘录）。**老报纸站 wayback 快照无 `<p>` 无正文 class 时的长行过滤提取法（母亲轮 2026-08 实测）**：nytimes.com 2010 老文章快照（20150423111345id_，71KB）`<p>` 提取 0 段、articleBody/nytd-articleBody 等 class 全无——解法：剥全部标签→按换行拆行→`len(strip)>80` 长行过滤（正文行长、导航/页脚行短），跳过首行浏览器升级提示（"NYTimes.com no longer supports Internet Explorer 8 or earlier"）即得正文（15 长行 5.5KB，含 Dargis 全部金句）；NYT 引号是弯引号（"Mother,"），norm 需删引号兜底。**同一句式多批评家共享时按署名源核验**：`the actual violence either occurs offscreen or passes so quickly that you'll miss it if you blink` 与 `In classic western style, the whole film moves toward a final showdown in the dusty village street` 同现于 Criterion（Sesonske）与 Ebert 两篇——凭印象署名会错挂，per-source grep 后再定归属（本例两段皆 Sesonske 文，Ebert 文无）。
   - **⚠️ Ebert 2013 年去世后 rogerebert.com 的影评不是他写的（消失的爱人轮 2026-08 实测）**：2014 年的 Gone Girl 影评实为 Matt Zoller Seitz（RogerEbert.com 主编）所撰——抓回先验 JSON-LD `"author"` + `"datePublished"` + 文末 byline 三证再归属引文，引用写「Seitz（RogerEbert.com）」而非「Ebert」；引文 grep 校验抓不到作者错误，归属靠写作时核验（与 ㊾ 双版本归属同族：同一站点不同作者的评论必须按作者署名，不能凭站点默认 Ebert）。
   - 猜文章 URL 全 404 时用 **Guardian Content API 发现精确 URL**：`https://content.guardianapis.com/search?q=<词>&tag=film/film&from-date=YYYY-MM-DD&to-date=YYYY-MM-DD&page-size=20&api-key=test`——api-key=test 免费可用，**必须带 tag+日期区间**否则返回无关新文；JSON 的 webUrl 即精确文章地址（是枝裕和轮影评/访谈 URL 全由此找到，配方见 playbook §7.7）。
4. **自述/访谈优先于影评**：导演自传节选（Criterion "From the Current" 旧文多为出版社节选授权转载）> 纪录片转述 > 影评人观察。黑泽明案例：Criterion《Akira Kurosawa on Rashomon》即自传《Something Like an Autobiography》节选——一手金矿（拍太阳/黑墨水雨/波莱罗/「人无法对自己诚实」全在里面）。
   - **导演自传/理论书全文 = Internet Archive DjVuTXT 一次到手**（塔可夫斯基轮实测：《Sculpting in Time》474KB 全文，10+ 条带页码原话直取——雕刻时光定义/反蒙太奇两段/梦境方法论；配方见 references/source-mining-playbook.md §7.7）——书籍全文 > 一切二手转引，优先于 Criterion 节选。
   - **维基 ref 里的非主流域名常是粉丝站一手访谈**（塔可夫斯基轮：nostalghia.com 的 Bachmann 1984 访谈、录音师 Sharun 访谈全文都在 Wikipedia ref 里）——grep refs 的域名，别只盯 archive-url。**The Kubrick Site（visual-memory.co.uk）= 库布里克一手技术文献通道（巴里·林登轮 2026-08 实测）**：DiGiulio《Two Special Lenses for "Barry Lyndon"》（American Cinematographer 原文，改造者本人）与 Ciment「Three Interviews with Stanley Kubrick」全文都在此站——wayback 快照是 JS 壳（2.6KB "Your browser doesn't seem to support Javascript!"），r.jina.ai 直抓 14KB 全文一次到手；同轮 ascmag.com 的 ASC 1976 原刊重刊（Lightman 文=Alcott 访谈）经 wayback 直抓 86KB——**电影技术史/摄影幕后类轮优先查这两站**（发现路径：英维 raw 的 ref 域名 grep visual-memory/ascmag）。**片方/院线官网的导演亲笔信 = 一手自述金矿（江湖儿女轮 2026-08 实测）**：英维《江湖儿女》ref 里 Landmark Theatres "Filmmaker Letter" 系列（landmarktheatres.com/ash-is-purest-white-filmmaker-letter）原链已死，archive-url 快照（20220118202012）秒回全文——贾樟柯亲笔信含"江湖"定义原话、童年帮派大哥原型（斌哥角色来源）、"江湖已生意化"观察，一手密度不输 Criterion essay；发现路径 = grep 维基 ref 域名（landmarktheatres/filmmaker-letter 关键词），死链一律走 archive-url。
   - **Criterion Current 作者页 = 导演亲撰文章入口**（是枝裕和轮实测）：`criterion.com/current/author/<id>-<slug>` 列出导演自己写的 essay（挖到其《下一站，天国》小说后记——"把虚构拍得像纪录片"）；criterion.com 搜索页/影片页/current posts **live 可直抓**（别被旧轮 JS 壳结论一竿子打死，按页 curl 验证体积与正文关键词，壳则走 CDX wayback；配方见 playbook §7.7）。**Cloudflare "Just a moment..." 壳（~5.5KB、`<title>Just a moment...` 签名）时 r.jina.ai 代理直抓 essay 全文成功（侯孝贤导演轮 2026-08：posts/8407/3754/7395/8403 四篇 7.7–30KB 全过）——CF 壳后 jina 是第一顺位兜底，WebBridge/CDX 次选**。**Criterion 早期 essay（post 号 <100）可能是导演亲撰第一人称节选（卡比利亚轮 2026-08 实测）**：posts/57-nights-of-cabiria 文末署 "Excerpted from I, Fellini (1995) by Charlotte Chandler"——导演访谈书节选授权转载（含《城市之光》影响自认、"女版夏洛"称号、被剪段落教会审查史、"auteur 一词最早出自巴赞评卡比利亚"等一手金矿）；**抓回后必看文末署名确认作者身份**——第一人称导演 essay 优先级高于影评人 essay，与步骤 4"导演自传节选 > 影评人观察"的排序一致。

## 卡片模板（8 节）

1. **风格签名**：一句话（例："暴烈天气入画当角色 + telephoto 压平的大写意构图 + 多机位同拍换来的剪辑爆发力"）
2. **美学体系**：构图/画面、运镜/调度、色彩/光线、声音/配乐、剪辑/节奏——每维度带 1-2 个成片实例 + 来源；建议用表格（手法 | 成片实例 | 取证来源）
3. **创作思路**：导演的工作方法/理念（自传/访谈/幕后，附原话与出处）
4. **桥段设计**：拆 2-3 个招牌桥段——设计逻辑（技术层/节拍层/主题层）+ 观众情绪如何被引导
5. **画面锚点**：5-8 个最强画面（一句话一个）
6. **可复用时机**：**适用创作场景归类**（哪类戏/哪个画面需求用哪招 + 证据出处）——泛用导向，不绑定单一项目
7. **AI 提示词对接**：美学语言 → Seedance 提示词写法（英文 prompt + 中文注，按构图/天气光线/色彩/声音节奏/群像分组）
8. **⚠️ 诚实声明**：来源局限（渠道没抓到/名言未验证/维基转引/剧本版本差异）

## 纪律（写卡片时）

- **引文必须是抓到的原文**（grep 出来或从页面剪贴），不许凭记忆写台词和名言。
- **编号纪律：S# 在抓取成功当下即分配并登记**进文末来源清单表（存档文件名↔来源↔关键内容）；写卡片时只引用已登记编号，绝不后期补编——晚期补号极易错引（是枝裕和轮：Criterion 影片页与 essay 页一度错挂同一编号，返工 3 处；写卡片前 `grep -o "\[S[0-9]*\]" 卡片 | sort -u` 与来源表对账）。
- **未验证的名言标「未取证到」，不写进正文**。黑泽明案例："Man is a genius when he is dreaming"（《梦》）与"艺术家不可移开目光"（自传）本次均未验证到原文 → 弃用并写进诚实声明。
- **区分一手与二手**：一手=自传节选/剧本原文/导演访谈原文；二手=维基转引（Galbraith/Richie 等，有页码）。转引注明"经维基转引，页码可信，原句措辞以转引为准"。
- **观感类描述引用评论家原话并保留人名**（Ebert/Jim's Reviews），注明"本代理未逐帧看片"。
- **版本差异**：流传英译本与上映版有出入需核查；剧本层事实与成片观感冲突时以剧本行号为准并注明。
- **任务预设的说法未取证到时**：不写进正文，改用取证到的真实签名重写该维度，并在诚实声明里逐条对照说明。科恩轮：「对称构图」未取证到 → 替换为隔离构图（三人几乎不同框）/ 正午无阴影均匀光 / 空旷景观渺小人物，均已声明；奉俊昊轮「帕赫贝尔卡农」同理。预设只是线索，取证才是答案。

## 手法体系深化（跨作品演变）变体

第八轮胡金铨案例实测。当任务要求"不要单部片分析，跨作品提炼演变脉络"时，产出 `<导演>_手法体系深化.md`，结构：

1. **创作路线归类**：从作品矩阵分 2-3 条创作线（如胡金铨：客栈空间线/禅意武侠线/女侠谱系），每条线 = 代表作 + 核心手法。**线的定义本身要找直接证据**（百度百科《迎春阁之风波》词条给出"客栈三部曲=大醉侠+龙门客栈+迎春阁"及三一律作剧法原话——一条线的存在证明往往藏在配角词条里）。
2. **手法演变脉络**：每条演变 = 跨片时间轴，**每个阶段单独带证据**；建议用表格（影片 | 年份 | 手法形态 | 证据）。量化数据优先（胡金铨案例：大醉侠均镜 5.6s vs 张彻独臂刀 6.3s，影评人皮特·里斯特统计，经豆瓣长评转引）；**缺量化的阶段明确标「未取证到」**（《侠女》均镜秒数无量化，改用定性证据：25 天实拍精剪 + 学者 Rodríguez 分析）。
3. **可复用工具箱**：**泛用导向**（2026-08-07 用户拍板"这些不是定向给X项目用的，是泛用的"——知识库是土壤层，服务所有创作），每条 = 取什么 + 怎么用 + **适用创作场景归类**（动作对峙戏/双雄戏/家庭戏/留白意境/群像戏/谈判戏各自对接，不绑定单一项目，禁止"对接XX项目"式定向表述）+ AI 提示词写法（提示词标注"按取证要点编写，非原片描述"）。
4. **vs 其他导演**：对比导演（徐克/黑泽明）时**优先复用本地已有导演卡片作转引链**（徐克卡片里的焦雄屏语、黑泽明卡片里的多机位数据），标注"经X卡片引"，避免重复抓取；对比维度选两人都有硬数据的点（快剪密度/特写用法/多机位）。
5. **⚠️ 诚实声明**：同主模板。

**变体纪律**：
- **提炼句与导演原话分离**："武打的终点是不战"是提炼句——须注明其事实基础（慧圆一指败敌、天女彩绳、烧经等有据桥段），不得当作胡氏原话引用。
- **演变论断必须逐阶段取证，不许凭印象推时间线**；演变弧线最好有导演原话做锚（徐克轮：快剪演变用 Film Comment"我们是紧张的人"+Criterion《刀》"not meant to be seen clearly"两段一手引文定首尾）。
- **预设演变链逐节点核对（王家卫轮）**：任务预设的具体节点要逐个对照取证——预设"惊蛰立秋"实为误记，节气序列是惊蛰→夏至→白露→立春（英维剧情+知乎互证）；节气字卡属 2008 终极版而非 94 原版（知乎：终极版才加字卡）。错误节点在正文显式纠正 + 诚实声明逐条对照。**预设片序时间线错误变体（库布里克深化轮 2026-08 实测）**：预设"古典乐错位（发条橙→闪灵；2001 的蓝色多瑙河）"的写作顺序隐含 2001 在后——实际年份 2001(1968)→发条橙(1971)→闪灵(1980)；演变链按真实年份重排，任务预设的片序只当线索不作时间线依据，纠正写入诚实声明。
- **百度百科合并抓取文件防张冠李戴（王家卫轮）**：导演条目常一次抓回多片连排的整串片目（dxxd_baike_main.txt 含多部影片段落），grep 命中关键句后**必须回看前文确认主语属于目标影片**——"全片以金色为主色调"经核属《心灵之境》非《东邪西毒》，险些错引；此坑同样适用于英文维基导演条目内多片段落。
- **对比节无第三方并列文献时的做法（徐克轮实测）**：vs 王家卫/胡金铨没有直接对比文献可抓时，用双方**各自已取证**的风格描述对照（本地《王家卫_导演美学卡片》的抽帧/慢镜 vs 徐克自述"紧张的人"），并在诚实声明里标注"本节为分析框架，非导演自述、无第三方并列文献"。
- **vs 节一手桥新渠道（科恩深化轮 2026-08 实测）**：挖目标导演自己单片维基条目里「对对比导演的评论」段——fink 维基记载科恩兄弟接受《闪灵》「空旅馆+写不出字的作家」类比、Joel 原话称其「在更整体的意义上属于恐怖片类型」，是 vs 库布里克节的最强锚点（一手桥 > 只转引对比导演自己的材料）；发现路径 = `grep -il <对比导演名> <目标导演存档>*`（`grep -il Kubrick coen_*` 一次命中 fink 三个存档）。
- **引文说话者归属核查（科恩深化轮纠错一例）**：引文里含导演名 ≠ 导演说的——「Ethan has described it as 'a surrealist vision'」实为「Critic Donald Lyons describes the film as 'a retro-surrealist vision'」（导演名出现在段落上文、说话者是批评家）；引文前一行的「Critic X describes...」主语结构即归属依据，引用署名以该主语为准（与晚春轮「同一句式多批评家共享按署名核验」同族，本条管导演名与批评家名同段混现）。

- **Ebert 老片影评 slug 可能按重映年份命名（卓别林轮 2026-08 实测）**：`great-movie-modern-times-1936` 404——正确 slug 是 **`modern-times-1972`**（Ebert 评的是 1972 年芝加哥重映而非 1936 首映），发现路径=Ebert《City Lights》Great Movies 影评正文内链（「[Modern Times](https://www.rogerebert.com/reviews/modern-times-1972)」）；**Ebert slug 404 时先查他其他影评正文的内链**（同作者互链常带正确 slug），再试重映年份变体，最后才走 CDX/wayback（与费里尼轮双连字符 slug、巴顿·芬克轮非 great-movie- slug 并列第三形态）。
- **校验脚本存档加载器须含 rexxar 长评 .json + norm 剥 ASCII 直引号/单方括号（卓别林轮 2026-08 实测）**：① load_archives 只 glob `.txt` 会把豆瓣长评（`chaplin_cl_review_*.json`）整个漏掉，中文引文集体假 MISS——加载器须并列加载 .json（json.load 后取 content 字段、剥标签、html.unescape），与 ⑨「rexxar JSON 须解码」互补（⑨ 管比对前解码，本条管加载器文件类型覆盖）；② norm 除弯引号/[[ ]] 外还要剥 **ASCII 直引号 `"` 与单方括号 `[` `]`**——Ebert 原文 `as his first "talkie"`、维基编者补全 `from [his] star image`、`Tramp [walking] optimistically` 都靠这两项才匹配（㊻ 编者方括号的 norm 实现级落点）；③ 测试短语切词吞字再证（「此前的角色常被批评为」vs 存档「此前在基石影业时期，他的角色常被批评为」——㊲ 同型，切点须从存档原文逐字取）。
