# 任务复盘方法论

## 适用场景

任务耗时远超预估、反复犯同样错误、用户明确要求反思时。

## 复盘维度（13个）

| 维度 | 内容 |
|------|------|
| 1. 事实还原 | 时间线+每个方法的结果+根因 |
| 2. 根因分析 | 逐层深挖（技术→指令→工具→决策→目标→上下文→本质） |
| 3. MoA/模型行为 | 哪些模型给了正面/负面建议，为什么没采纳或采纳错了 |
| 4. 跨项目对比 | 同模式在不同项目中的表现对比表 |
| 5. 自我欺骗模式 | "不说了直接做"→继续分析等具体模式 |
| 6. Skill/Memory遵守率 | 定量统计（如0/4=0%） |
| 7. 工具调用效率 | 有效推进 vs 无效探索比例 |
| 8. 用户纠正响应延迟 | 用户说第几次才真正改变行为 |
| 9. 跨任务学习失败 | 同一模式跨项目重复出现 |
| 10. 认知过载 | 同时做几件事导致每件都做不好 |
| 11. 上下文压缩破坏性 | 压缩后丢失信息导致的重复探索 |
| 12. 锚定效应 | 第一个方案锚住后迟迟不换更简单方案 |
| 13. 解决方案 | 每个问题对应具体的行为改变机制 |

## 黄金规则

- **根因不满足于表面**：找到"为什么没有用已验证方法"而不是"SPA重定向"
- **解决方案必须可触发**：不能是"下次注意"，必须是"X场景下自动做Y"
- **交叉验证**：同一个失败模式出现在多个项目中 → 系统性问题
- **产出位置**：Obsidian vault `Hermes运维/` 下

## Pitfalls

- 复盘本身不能成为新的分析循环。写完=做完。
- 不用每个小任务都写13维度。只有明显失败/被纠正的任务才需要。
