## 本轮新坑七例（校验与调试层）

1. **MSYS bash heredoc 篡改 CJK 码点（Windows 宿主专用）**：经 heredoc 传中文进 python stdin 时，U+500B 個 被 shell 层转成 U+4E2A 个，导致"replace 不生效""短语明明在存档里却 MISS"的假象；终端 stdout 渲染同样会骗人（同一字符在 DIFF 行与 repr 里显示不同）。解法：调试脚本一律 write_file 落盘、中文用 `\u` 转义书写、关键比对用 hex 字节级输出（`.encode('utf-8').hex()`），不依赖终端显示。
2. **opencc-python-reimplemented = 手写繁简表的终极替代**：手写 T2S 表缺字（兒絕殺數…）是假 MISS 长期来源（㉒/㊵②/㊿-盗梦 各坑同源）；`python -m pip install opencc-python-reimplemented`（注意：pip 可能装进系统 Python 而 `python` 解析到 hermes venv——必须 `python -m pip install` 装进当前 venv 并 `python -c "import opencc"` 验证）后 `opencc.OpenCC('t2s')` 一步归一。norm 管道首步即 t2s。
3. **占位句自检（防全绿假通过）**：校验清单里故意放 2-5 条不存在的占位句（如"它是我们的结局"），跑完必须全部 MISS——证明脚本真的在比对；全绿且占位句也"通过"= 脚本失效。本轮 5 条占位句全部命中 MISS，自检成立。
4. **存档侧代词性别以原文为准（㊲ 实例扩展）**：长评以「她」指代女性化角色程蝶衣（"她自始至终都没有被时代改变过"），校验短语写「他」即假 MISS——短语必须从存档逐字复制，代词性别不许按常识改写。
5. **enwiki grep 命中但 normed 未命中的调试路径（㊶ 调试补充）**：①先 `re.findall(r'<ref[^>]*>', raw)` 与 `raw.count('</ref>')` 计数配平（配平≠安全：跨 `<ref>` 的远配对仍会吞正文，见下）；②逐阶段打印短语存活性（ref→tag→wikilink→template→标点），定位吞文阶段。本轮 zhwiki 6 开 6 闭配平却仍丢「成全自個兒」——真凶是 heredoc 码点篡改（坑 1），证明"先怀疑调试环境再怀疑 norm"。
6. **对谈类长评标题选稿「评/对談」**：华语片无导演访谈时的隐藏一手通道再添一例——关锦鹏×张国荣 BFI 百年访谈文字转帖（review/1615230，832 有用）含演员论导演一手原话（结尾改动之争：「我曾經極力要求保留兩個男人在澡堂的一段對話」；陈凯歌解释=若段小楼自杀会凸显角色最伟大；「程蝶衣其實是個很積極的人」）。选稿标题关键词扩展到「评」+「对談/對談」。
7. **自动提取盲区补检（0 MISS 定稿前第二道闸）**：手写清单之外，从成稿自动提取「」/"" 内引文段（CJK 占比判定语言）路由存档；若 MISS 全为提取伪影（引号间夹自己的评述文字/加粗分析句），即证明主清单完备。本轮手写 167 条 + 自动补检 0 真漏。
