# 布局与信息架构

> 2026-08-10 | 面向：工具型 UI 布局——密度、栅格、间距、导航层级。本工作区基准：宽屏双栏、参数常显不折叠、空间利用率优先。
> 来源标注：训练知识（8pt 网格规范、NN/g 眼动研究、Material Design 3）

## 一、密度原则（工具 UI 的核心）

| 原则 | 逻辑 | 出处 |
|---|---|---|
| 信息密度 > 大留白 | 工作工具追求一眼看到更多，消费型页面才追求呼吸感 | NN/g, "信息密度"研究：不同任务对密度的容忍度不同 |
| 参数常显不折叠 | 工作流中间步骤被折叠 = 认知负担转移给用户记忆 | Nielsen #6（识别优于回忆） |
| 默认值合理 | 常用参数给合理默认，用户只改例外项 | Nielsen #7（灵活与高效） |
| 密度可调 | 紧凑/舒适两档密度切换，比一刀切更稳 | Material Design 3 密度规范 |

## 二、栅格与间距系统（8pt 网格）

| 概念 | 取值 | 出处 |
|---|---|---|
| 基础单位 | 8px（间距/边距/尺寸全部是 8 的倍数） | Material Design 3, "Layout" |
| 紧凑密度 | 4px 步进（列表项 32px 高、紧凑表格行 28-32px） | 同上（density 规范） |
| 栅格列 | 内容区 12 列 / 工具面板 4-8 列，宽屏双栏 = 左内容右参数 | 同上 |
| 断点 | 工具 UI 优先适配 1280px 以上，不追手机 | 见 [[可访问性与跨屏适配]] |

**为什么 8pt**：8 的倍数在 1x/2x 屏上都整除，对齐稳定；4px 作子步进给紧凑密度。这是 Material/各大设计系统（IBM Carbon、Fluent）共识。

## 三、信息层级（人怎么扫页面）

| 模式 | 逻辑 | 出处 |
|---|---|---|
| F 型阅读 | 浏览型页面：用户先横扫顶部、再沿左侧竖扫——标题/关键操作放顶部与左侧 | NN/g 眼动研究, 2006/2017 |
| Z 型路径 | 视觉均衡的页面（登录、首屏）：左上→右上→左下→右下 | NN/g 眼动研究 |
| 层级三件套 | 字号 + 字重 + 颜色明度 三选二变化即可分主次，三样全变是过度设计 | NN/g, "Visual Hierarchy" |
| 就近原则 | 相关控件放一起、不相关分开——人按空间距离判断关联 | 格式塔邻近性 |

## 四、导航与框架（工具 UI 的骨架）

| 模式 | 逻辑 | 出处 |
|---|---|---|
| 左导航 + 右内容 | 工具型双栏：左侧导航/列表，右侧内容区——符合 F 型扫描 | NN/g 导航研究 |
| 三栏（导航+内容+参数） | 创作/配置类工具可用，但**参数栏必须常显**，不折叠成图标 | 本工作区实测偏好（TTS 工具迭代五版结论） |
| 标签页 | 用于平级视图切换（≤5 个）；超过则收进下拉 | NN/g, "Tab Design" |
| 面包屑 | 层级 >2 层且用户需要回跳时用；平级工具不需要 | NN/g 面包屑研究 |
| 无限滚动 vs 分页 | 浏览型用无限滚动，查找定位型用分页 | NN/g, "Infinite Scrolling Is Not for Every Website", 2018/2024 |

## 五、分组与命名

| 要点 | 逻辑 |
|---|---|
| 分组 ≤5-7 组 | Miller 7±2：人一次能处理的组块上限（[[UI交互设计逻辑与动效]] 套1） |
| 组内元素 ≤7-9 个 | 同上，超出用「更多」折叠 |
| 命名直白 | 用户能按名字猜出功能，比创意命名重要（Jakob 定律：沿用惯例） |
| 顺序稳定 | 导航顺序跨页面不变，用户形成肌肉记忆 |

## 六、实战对照（本工作区偏好 → 权威依据）

| 既定偏好 | 依据 |
|---|---|
| 宽屏双栏、参数常显不折叠 | 密度原则 + Nielsen #6 + 就近原则 |
| 空间利用率优先、宁可信息密 | 密度原则（工具型任务容忍高密度） |
| 无限滚动替代分页 | NN/g 2018/2024 |
| 反感三栏/标签页/花哨动画 | 工具型 UI 简化导航层级（≤5 标签、两栏够用） |
| 记忆上次视图/筛选/搜索词 | 见 [[UI交互设计逻辑与动效]] 套2 |
