# 人物研习卡片 · 取证式研究流程（Master Card Research）

## When to Use（何时用）
- 任务要求为某位影视行业人物（导演/剪辑师/调色师/声音设计师等）产出「XX_制作大师卡片.md」式研究文档
- 需要「每条论断带来源编号 + 原文摘录 grep 验证 + 诚实声明」的取证纪律
- 知识库大师卡片扩展轮（如 `_work/制作大师研习-*/` 目录轮次，子代理分工）

## 工作流（编号步骤）
1. **先读模板与规范（铁律）**：找同体系既有卡片作结构模板（本例：`AppData\Local\hermes\skills\妖玉影视\_知识库\references\制作学科\大师卡片\Murch_制作大师卡片.md`），读轮次 `规范.md`。结构固定八段：①专业签名 ②美学体系表（手法|成片实例|取证来源）③创作思路（附原话+出处）④招牌作品拆解 ⑤可复用时机 ⑥AI 提示词对接 ⑦诚实声明 ⑧取证来源清单。
2. **检索来源**：维基主条目 + 官网传记 + 本人访谈（一手全文）> 深度行业报道 > 维基转述。后期工种（调色师等）特别优先：访谈播客（Dolby Creator Talks、LBB、Post Magazine、The Making Of）、公司官网 news/纪实页、HPA/ASC/AMPAS 奖项报道、公司 wiki 条目（组织史=人物史）。
3. **批量存档**：`curl -sL -A "Mozilla/5.0..." -o pages/<名>.txt "https://r.jina.ai/<url>"`，每批 4-8 个 URL，循环+间隔 1.5s；存档后抽查文件大小与开头，确认正文渲染成功。⚠️ **execute_code 循环模式（2026-08 Morricone 轮验证）**：抓取建议写进一个 execute_code 脚本——`for fname, url in dict.items(): if os.path.exists(fname) and size>20000: print(SKIP); continue; curl...; sleep(8)`。好处：①已存在文件跳过=断点续抓，脚本可反复重跑不浪费；②一次工具调用抓完一批（14 页仅 3 次调用）；③**维基主条目等大页面（90KB+）间隔 8s+ 防 r.jina.ai 429**，小页面可降到 3-5s；④成功判据 `len(txt) > 5000`，短输出打印前 200 字符诊断。⚠️ **r.jina.ai 兜底链（2026-08 验证）**：若存档文件开头是 `<!DOCTYPE html>...<title>Just a moment...`（Cloudflare 挑战页，全部目标站同批中招=r.jina.ai 通道失效，非站点反爬），不要放弃，改**直连 curl**——绝大多数站点（新闻/影评/博客/电影网站，含 Cloudflare 保护的 filmstage）直连带 UA 即可抓。另见（2026-08 Rydstrom 轮）：jina 还偶发返回 ~240 字节极短 stub（无 "Just a moment" 字样，如 blogspot/vulture 当批 2-3 个文件同时 242B）——同样换直连 curl 带 UA，判据 `wc -c < 500` 即换通道。各通道优先级：
   - 直连 curl：`curl -sL -A "$UA" -o pages/<名>.html "<url>"`，然后 python3 + BeautifulSoup 转文本（html2text 常未装，bs4 基本可用；先 decompose script/style/nav/footer/header/noscript，再 get_text('\n') + 压缩连续空行）。每个来源同时留 .html 原件与 .txt 正文。
   - ⚠️ **直连成功后禁止再跑 fallback 覆盖（2026-08 李屏宾轮踩坑）**：批量脚本里「直连成功」的判断**不能**拿「头部前 100 字符不含 `<!DOCTYPE html>`」当成功条件——正常 HTML 页面本来就以 `<!DOCTYPE html>` 开头，会把已抓好的 500KB 正文误判为失败、触发 r.jina.ai fallback 并**覆盖成 6KB Cloudflare 挑战页**（当批 6 个文件全毁，被迫重抓）。正确失败判断：`size < 500` 或头部含 `Just a moment`；更稳做法：fallback 写进**不同文件名**（如 `<名>_jina.txt`），永不覆盖直连结果。
   - ⚠️ **r.jina.ai 截断可重试（2026-08 Prieto 轮验证）**：jina 返回正文若尾部带 `[truncated]` 标记或句子中断（如止于 "…even more invisible. Th..."），**同 URL 重试一次（加大 --max-time）常可得全文**——是服务端渲染波动，非页面固有截断；与「新浪旧文 jina 常截断」记录互补：先重试再放弃，重试仍截断才换源/标「未取到」。若脚本判「直连 OK」但正文提取后发现是 Cloudflare 挑战页（5KB+ 的 HTML 也能过 size 检查），判据看头部是否含 `Just a moment`，不是只看字节数。
   - 维基用 `https://en.wikipedia.org/w/index.php?title=<条目>&action=raw` 拿 wikitext（纯文本可直接 grep，比 HTML 转换干净）；中文维基同样可用，注意简体条目可能只是 43 字节 `#REDIRECT [[繁體名]]`，要跟到繁体条目再取。⚠️ **中文维基 `action=raw` 直接请求中文标题有时返回 Wikimedia Error（HTML 而非 wikitext，2026-08 实测）**；改用 API：`https://zh.wikipedia.org/w/api.php?action=query&prop=revisions&rvprop=content&format=json&titles=<urllib.parse.quote(标题)>&rvslots=main&redirects=1`。正文在 JSON `revisions[0].slots.main.content`——**字段名是 `"*"` 不是 `"content"`**（直接 json.loads 按 content 取会 KeyError）；提取法：正则抓 `"\"\\*\":\"((?:[^\"\\\\]|\\\\.)*)\""` 再 `json.loads('"'+m.group(1)+'"')` 反转义，或整包 json.loads 后按 `"*"` 键取。中文维基另有一条无 API 通道（2026-08 Dangal 轮验证）：**页面 HTML 直抓**——`curl -sL "https://zh.wikipedia.org/wiki/<percent-encode 标题>"` 拿 952KB 完整 HTML、无 429 限流，正文正则取 `<div id="mw-content-text">` 至 `<div id="catlinks"` 之间 → 剥标签 → html.unescape → 压空白；⚠️ 转出文本 infobox 区域逐词拆行，grep 前必须去全部空白；⚠️ 简体标题的条目正文可能是繁体（「摔跤吧！爸爸」条目即繁体呈现），检查串用条目实际语言形态。另：action=raw 遇重定向目标为**消歧义页**时（`Dangal_(film)` → 88B `#REDIRECT [[Dangal]]`，而 [[Dangal]] 是消歧义页），读消歧义页内容即可拿正确条目名（`Dangal (2016 film)`），比 API 搜索省事（API 彼时还在 429）。
   - ⚠️ **英文维基批量 API + 429 限流（2026-08 Prieto 轮验证）**：多条目批量抓同样可用 API（`en.wikipedia.org/w/api.php?action=query&prop=revisions&rvprop=content&format=json&rvslots=main&redirects=1&titles=<urllib.parse.quote(标题)>`）——`redirects=1` 自动跟重定向（action=raw 遇重定向只给 32B 页，如「Lust, Caution (film)」→「Lust, Caution」），正文在 `revisions[0].slots.main["*"]`；但循环连发会 429 Too Many Requests（是限速不是死路），**每条间隔 5-8s 或降速重试即可**；标题不存在的条目 API 返回 `missing` 字段——可快速终结「人物中文名变体试错」（「羅德里哥·普里耶托」「羅德里戈·普列托」均查无，中文维基无此人独立条目），别反复试变体。
   ⚠️ **单条目 action=raw 变体（2026-08 奚仲文轮）**：①英文维基条目名大小写变体（`Yee Chung-Man` → 正确名 `Yee Chung-man`）action=raw 只回 44 字节 `#REDIRECT [[正确名]]`——文件过小先看头部，直接跟到重定向目标名再抓；②中文维基 API 偶发限流（返回 278 字节 \"You are making too many requests to the API.\"）——等待数秒重试或直接改 `action=raw` 单条抓取，raw 不受 API 限流影响。
   ⚠️ **官方研究 PDF 存档（2026-08 奚仲文轮验证）**：香港电影资料馆 Filmmakers Search（filmarchive.gov.hk）等官方研究 PDF 是港片影人金矿——curl 直连可下、pymupdf 提取（`import pymupdf`；`import fitz` 名已弃用但仅警告不致命）；但 **PDF 每行末尾有换行**，验证归一化必须先 `re.sub(r'\s+', ' ')` 压空白，否则多词引语全批假失败（首验 5 条 MISS 中 2 条即此因）。
   - **中文旧站点（新浪等）是 GBK/gb18030 编码**：`raw = open(f,'rb').read(); html = raw.decode('gb18030')` 后再进 BS4，否则全文乱码、grep 中文必然 0 命中。解码失败再试 utf-8。⚠️ 已用错误编码落盘的乱码文件（锟斤拷）无法二次解码挽救——直接重抓原始字节再解码（2026-08 程小东轮 sina_bio2008 实例）。
   - 中文字符串里可能夹 `\r\n`（Windows 换行），grep 时留意。
   - **Wayback 直取（2026-08 Deakins 轮验证）**：被墙/反爬页面先 `https://archive.org/wayback/available?url=<url>` 预检（连发会 429 限速，间隔 3s+），确认有快照后取 `https://web.archive.org/web/<年份>id_/<url>`——IMDb fullcredits 用 `web/2020id_/` 可拿到 700KB+ 完整职员表（直连 0 字节、jina 被 Cloudflare 拦时此路可靠）。⚠️ 无快照时 `id_` 请求返回「Wayback Machine」着陆页（~151KB，`<title>Wayback Machine</title>`，文件头是 JS 脚本）——不是目标内容，先看标题或字节数判断，别把着陆页当正文存档。⚠️ **已死站旧文章返回导航/frameset 残页时迭代时间戳（2026-08 程小东轮验证）**：Wayback 取回 1-3.5KB 的「Kung Fu Cinema » Home」导航壳≠没存档——正文没渲染只因该 capture 只剩 frameset 壳；迭代不同时间戳（`web/<ts>id_/`），**优先最早 capture**（20040624id_ 一次取回 28KB 全文，而 2007 年的 capture 只剩壳）；判据=字节数 <6KB 或正文关键词缺失时换时间戳，别放弃。
4. **署名查证（重要，别跳）**：任务简报/上下文里的「谁调色/谁剪辑了某片」归属**可能错误**。写作前对关键影片用 IMDb 完整职员表查证：`r.jina.ai` 抓 `https://www.imdb.com/title/<ttid>/fullcredits`，grep 人物名与角色词（colorist / digital intermediate / editor）。查证结果与简报冲突时：卡片**按查证结果写**，加「查证框」+ 诚实声明条目，绝不沿用简报的错误归属。实例见 references/sonnenfeld-session-2026-08.md（《银翼杀手2049》勘误）。
   - **双署名/被替换主创（2026-08 杜可风轮验证）**：①多摄影（或多剪辑）影片要查**分段归属**——同一部片不同段落可能由不同 DP 拍摄（《重庆森林》第一段抽帧实为 Andrew Lau，杜可风只拍第二段，中文互联网普遍误归杜可风）；②中途退出/被替换的主创，**影片自己的维基条目 Production 段**常写明（《花样年华》条目：Doyle 超期退出、由 Mark Lee Ping-bin 接手、「成片主调归 Lee」）——人条目查不到就查片条目，互为交叉验证；③中英维基数字口径可能不一致（杜可风金像奖次数：英维基 "six times" vs 中维基列 7 部获奖片）——卡片按来源各引、注明口径差异，不强行统一。
   - **任务简报的影片归属可能是张冠李戴（2026-08 种田阳平轮验证）**：简报把《姑获鸟之夏》《新哥斯拉》安到美术监督种田阳平头上，查证后均不成立——姑获鸟之夏(2005)美术实为池谷仙克、新哥斯拉(2016)美术实为林田裕至/佐久嶋依里（第40回学院奖最佳美术得主），人物条目作品列表里根本没有这两片。查证路径：①人物条目作品列表无此片时，**直接查影片自己的维基条目制作人员段**——日本电影用日文维基 raw（`https://ja.wikipedia.org/w/index.php?title=<片名>&action=raw`），スタッフ段逐行列監督/美術/撮影，一 grep 便知归属（本方法对日系影人/影片比 IMDb 更快更全）；②百度百科日语版（`baike.baidu.com/ja/item/<片名>`）搜索摘要可快速辅助确认日本电影美术署名；③确认不成立后，卡片按查证结果写，另加「任务简报勘误」诚实声明条目，并补上该人物真实对应的同题材作品（种田的灵异题材代表作实为《怪谈》2007 中田秀夫）。
   - **「御用摄影」简报的跨导演归属核查（2026-08 Prieto 轮验证）**：简报称普列托（李安御用）拍了《少年派》《沉默》《爱情与灵药》——查证：《少年派》摄影实为 Claudio Miranda（凭此获奥斯卡最佳摄影）；《沉默》是斯科塞斯作品（普列托摄影、奥斯卡提名）；《爱情与灵药》不在其维基主条目完整片单（1996-2024）。普列托与李安的合作实为《断背山》《色戒》两部。验证路径：①人物维基主条目**完整 filmography 对照简报片单**（无此片=高度可疑）；②单片条目 infobox `cinematography =` 字段交叉（断背山/色戒条目均列 Prieto）；③被误安的导演作品查导演条目。修正后表述：「李安好莱坞时期两部作品的摄影」而非「御用」，勘误写入诚实声明。
   - **助手期 vs 监督期署名（2026-08 村木与四郎轮验证）**：日文维基人物条目作品表常分「美术助手作品」「美术监督作品」两段——简报把《七武士》(1954) 安为村木与四郎代表作，实为**美术助手**（美术监督是松山崇）；《罗生门》(1950) 亦为松山崇（村木 1954 年才升任美术监督，黑泽明组美术统计：村木 14 本/松山崇 5 本，见黑泽明日文维基）。查证要点：**生涯段写明「X年美術監督に昇進」之前年代的影片，先怀疑是助手署名**；人物条目没有的片 → 片条目スタッフ段交叉验证（同种田阳平轮方法）。
5. **摘录 grep 验证**：所有将写入卡片的英文原句逐一 grep 存档文件，不许凭记忆。
   ⚠️ **弯引号陷阱**：网页转存常含弯引号（' ' " "），grep 整句会假失败。对策：用不含引号的部分片段匹配，或把撇号换成通配符（如 `grep "It.s my third movie"`）。出现「应命中却 0 结果」先怀疑引号差异，不是来源缺失。
   ⚠️ **批量验证的引号归一化法（2026-08 Prieto 轮验证，推荐主法）**：单条猜通配符效率低；验证脚本先对 corpus 全文与全部检查串统一归一化——`s.replace('\u2019',"'").replace('\u2018',"'").replace('\u201c','"').replace('\u201d','"').replace('\u2014','-').lower()`，再逐条 `in` 匹配。Prieto 轮 73 条摘录一次跑完：7 条首验 MISS 全部为弯引号假阴性（含 `It's`、`DI's`、`He'll`、`director's voice`），归一后 0 MISS。直连 HTML、jina markdown、维基 wikitext 混存的存档引号形态各异，此法一劳永逸，比逐条改检查串可靠。
   ⚠️ **NFKC 归一化不对称陷阱（2026-08 Dangal 轮，全批假失败元凶）**：corpus 做 `unicodedata.normalize('NFKC', ...)` 而检查串没做 → NFKC 会把中文全角标点（，。（））转成半角（,.()），自然写法带全角逗号的中文检查串必然全批假 MISS（实测 49 条 35 条全灭）。对策：**语料与检查串共用同一个 norm()**（NFKC + 去全部空白），或中文片段避开标点只查主干。另：中文维基 HTML 转出的正文（见工作流 3 的通道）infobox 区域逐词拆行，同样靠「两侧去全部空白」解决。日文存档另有三类变体（2026-08 男鹿和雄轮 + 梶浦轮）：**日文直角引号「」『』**（原文「速く」写成『速く』假失败）与**重音字符**（déjà vu 写成 deja vu 假失败）——归一化函数加 `unicodedata.normalize('NFKD')` 分解 + 剥 combining marks（`re.sub(r'[\u0300-\u036f]','',s)`）+ 剥全部引号类字符（`"'「」『』`）。
   ⚠️ **日文 HTML 词内散落空格（2026-08 梶浦轮验证）**：原文排版在日文词内插空格（「妖しい音 を奏でている弦」「す ごく妖しげな」），验证只折叠空白仍假 MISS——日文引语验证统一「全部去空白」（`re.sub(r'\s+','',s)`）再匹配。
   ⚠️ **markdown 强调符陷阱（2026-08 Williams 轮验证）**：r.jina.ai 存档是 markdown 化正文，引语内单词可能带斜体标记——`it's what you _needed_ to write`，grep "needed to write" 假失败。对策：片段避开可能被强调的单词，或先 grep 无标记部分。「应命中却 0 结果」的第二号嫌疑人（弯引号之后）。
   ⚠️ **维基 markdown 链接包裹陷阱（2026-08 Morricone 轮验证）**：维基经 r.jina.ai 转存后，人名/物名/片名被 `[链接文字](url "title")` 包裹——原文 `whistling by [Alessandro Alessandroni](https://...)`、`howl of a [coyote](...)`、`plays a [pan flute](...)`，grep 完整短语必然假失败。对策：验证片段取链接文字**之前**的核心部分（`whistling by`、`howl of a`、`plays a`），或先 `re.sub(r'\[([^\]]*)\]\([^)]*\)', r'\1', txt)` 剥链接再验证。第三号嫌疑人。
   ⚠️ **维基 wikitext 双括号链接陷阱（2026-08 奚仲文轮验证）**：action=raw 存档里链接是 `[[Double Ninth Festival]]` 双括号形态，markdown 链接正则剥不掉——检查串 `when autumn comes on double ninth festival` 对原文 `when autumn comes on [[double ninth festival]]` 假失败。对策：norm 里加 `re.sub(r'\\[\\[([^\\]|]*)\\]\\]', r'\\1', s)` 双括号剥除（含 `[[链接|显示文字]]` 管道形态，剥为显示文字），与 markdown 链接剥除并列。英文维基 action=raw 档案必查此项。
   ⚠️ **维基管道链接正则 bug + HTML 标签剥除（2026-08 Letteri 轮，10 条假 MISS 定位链）**：①贪婪版双括号正则 `\[\[([^\]|]*)(\|[^\]]*)?\]\]` 对 `[[Richard Taylor (filmmaker)|Richard Taylor]]` 剥除失败（残留 "(filmmaker)"）——改用非贪婪+lambda：`re.sub(r'\[\[([^\]|]*?)(?:\|([^\]]*))?\]\]', lambda m: m.group(2) or m.group(1), s)`；②norm 必须加 `re.sub(r'<[^>]+>', ' ', s)` 剥 HTML 标签——markdown 链接剥除只覆盖 `[x](y)`，对直连存档的 HTML `<a>` 包裹（"Lord of the Rings" 被 `<a href>` 包住）无效，是 HTML 档假 MISS 的元凶；③检查串里原作者方括号注释（如 "Andy [Serkis] just recording"）要**保留方括号**照抄，删掉它反而匹配不上 corpus。
   ⚠️ **维基 wikitext 斜体标记 `''` 陷阱（2026-08 哈利豪森轮，首验 1 条假 MISS）**：action=raw 存档里斜体用双撇号包裹（`no ''Star Wars''`），连续子串检查串「no star wars」必假失败——与 markdown 强调符陷阱同族但形态不同。对策：norm 里加 `re.sub(r"''", "", s)`（在剥 [[链接]] 之后），维基 wikitext 语料必查此项；该轮首验 39/40 唯一 MISS 即此因。
   ⚠️ **检查词形态陷阱（2026-08 Morricone 轮）**：验证短语必须与原文**确切形态**一致——原文 `allowed the music to shape the film's rhythm`，检查串写成 `shaping the film's rhythm` 会假失败。对策：从存档文件复制原文片段作检查串，不凭记忆改写。第四号嫌疑人。
   ⚠️ **繁简体变体陷阱（2026-08 李小龙轮）**：中文档案验证时，检查串与存档的繁/简形态不一致会假 MISS——本轮检查繁体「連消帶打」对简体存档「连消带打」报失败，实为同一词。对策：批量验证脚本对中文片段先做繁简归一（或两个变体各查一次），再判 MISS。第五号嫌疑人。
   ⚠️ **HTML 实体陷阱（2026-08 Menke 轮验证）**：r.jina.ai 对 WordPress 等博客页常回**原始 HTML 而非 markdown**（文件名 .txt 但内容是 `<p>` 标签堆），存档里 `&nbsp;`、`&#8217;`、`&#039;`、`&hellip;` 等实体未解码——grep "constantly unfolds" 对 `constantly&nbsp;unfolds` 必然假失败。对策：验证前先 `html.unescape`（python html 模块）或把检查串拆成不含空格/撇号的片段；判定"应命中却 0 结果"时先 grep 更短片段 + 打印上下文确认实体形态，别直接判来源缺失。第六号嫌疑人。另：WordPress 页正文提取法——正则抓 `<p>(.*?)</p>` 段落或定位文章正文起点（如 `August 5, 2019 by <作者>` 之后），剥标签+解实体+压空白，一次成型可读正文。
   ⚠️ **引语措辞逐文件核验（2026-08 Williams 轮）**：写入来源清单/诚实声明前，同一事实的多源措辞差异要逐文件 grep——"two-note double-bass ostinato" 属 New Yorker、维基主条目写 "two-note ostinato"、中文维基写"大提琴"，误归属会在声明里露馅。同物多口径：三说并存、各归其源，不强行统一。
   ⚠️ **Windows 执行环境**：execute_code 里 subprocess 可能调不到 grep 可执行文件（WinError 2「系统找不到指定的文件」）——不要为此装 grep，改用 Python `re` 逐行匹配（flags=re.I，输出行号），效果等价；写卡片前把全部引语片段集中跑一遍验证脚本，一次性打印 MISS 清单（Storaro 轮 89 条片段一次跑完全过）。另（2026-08 Menke 轮）：本环境 search_files/rg 对含中文的路径报 IO 错（os error 3），中文目录下的文件定位/搜索改用 read_file 或 Python open() 直接读，验证脚本一律 Python 处理。
   ⚠️ **inline python -c 引号嵌套陷阱（2026-08 Zimmer 轮，全批假失败的元凶）**：execute_code 里 `python -c "...{q!r}..."` 传含撇号引语（Python repr 后）会被外层 bash 引号截断——表现为**全部检查无报错地失败**（exit≠0、无 stderr 线索），极误导。诊断法：先跑一条最简 grep（`grep -c '短片段' 文件`）确认文件可读且命中>0，再怀疑脚本引号。对策：验证脚本一律 write_file 成 .py 再 `python file.py` 执行，永不用 inline -c 传含撇号字符串。
   ⚠️ **卡片侧验证用子串判定（2026-08 Zimmer 轮）**：卡片摘录常是存档完整句的合法子串（`was more than just a soloist` ⊂ `She was more than just a soloist`、`signature or a leitmotif` ⊂ `use this song as a signature or a leitmotif`）——两侧分开跑：存档侧用完整句 `in`，卡片侧用子串 `in`，否则误报一片；另注意**同轮来源标点形态逐文件不同**（GQ 直撇号 it's vs MusicTech/ThePlaylist 弯撇号 it’s vs 维基直引号），修卡片时逐条对齐存档字节（弯/直），别凭记忆统一；**引语归属文件要查准**（`became the blueprint for all action movies` 在 BRAAAM 专条不在主条目），归属错→假 MISS→误改卡片。
   ⚠️ **维基 wikitext 自闭合 ref 陷阱（2026-08 Dykstra 轮验证）**：验证脚本剥 `<ref>` 引用时用 `<ref[^>]*>.*?</ref>`（re.S）会把自闭合 ref（`<ref name="eight"/>`）误当开标签，`.*?</ref>` 一路吞到下一个真 `</ref>`，**误删大片正文**→多条「应命中却 0 结果」（本轮 S10/S11 共 4 条假 MISS）。对策：先单独正则剥自闭合 `<ref[^>]*/>`，再剥成对 `<ref>...</ref>`；或首验 MISS 时直接回查原始 wikitext 文件 `find()` 确认存在再判。第七号嫌疑人。⚠️ **更彻底的解法：两步安全剥离（2026-08 Skyfall 轮）**——`re.sub(r'</?ref[^>]*>',' ',s)` 只剥标签、保留 ref 内部文本（cite 模板不在引文里，留着无妨），一次正则同时处理自闭合与成对、且不会因未闭合/跨行 `<ref` 标签吞正文（`[^>]*>.*?</ref>` 方案里 `[^>]` 含换行，未闭合标签会吞到下一个 `>` 为止）——wikitext 语料统一用此法。
   ⚠️ **旧站转录 mojibake 撇号变「?」（2026-08 Dykstra 轮验证）**：TheForce.Net 等 2000 年代转录站把弯撇号转成 `?`（`It?s`、`wasn?t`），归一化没清 `?` 就假 MISS。对策：验证片段避开撇号部分（如 `too small a community to have hostility`），或归一化时把 `?` 一并替换；转录站文件标「摘录级引用」并把 mojibake 原样写进诚实声明。第八号嫌疑人。
   ⚠️ **旧杂志 HTML 首字放大残留（2026-08 Dykstra 轮）**：老刊文章（ASC 1977 等）经 HTML 转文本后 drop cap 会把 "In" 拆成 "I n"。引文用避开残留的子串（`June of 1975, I was contacted`），并在诚实声明注明「按语义校正」。第九号嫌疑人。
   ⚠️ **wikitext 模板/弯引号/合并引文三坑（2026-08 Skyfall 轮）**：①**`{{convert|300|ft|m|adj=on}}` 类模板：wikitext 参数形态 ≠ 渲染文本**（渲染为 "300-foot"）——引文若含模板参数数值（"300 ft drop"）必假 MISS，引文截到模板前或先剥模板（剥后 "300 ft" 消失，引文措辞需随之调整，诚实声明注明模板差异）；②**`''斜体''` 标记**（`''Skyfall'' was part of...`）norm 里加 `re.sub(r"''",'',s)`（与哈利豪森轮记录同，此处并列为 wikitext 必查项）；③**文档引文用弯引号时，提取正则须同时匹配弯直**：`[“"]([^”"]{25,})[”"]`，只写 `"[^"]+"` 会漏掉一半弯引号包裹的引文、验证样本残缺；④**跨段合并引文（省略号拼接两句原文）在滑动窗口验证时仍会 MISS**——文档侧拆成独立引文，或在引文内标注省略位置，别依赖「省略号=可接受」（Skyfall 轮修正 3 处：Craig 两句间有 "says Craig" 插入、Powell 两段引语、剧本丁尼生诗句分句）。
   ⚠️ **scriptslug 剧本 PDF 直链（2026-08 Skyfall 轮，与 tdat 轮「scriptslug 反爬 HTML」记录互补）**：scriptslug 脚本页 HTML 内 grep `href="([^"]*assets/scripts[^"]*)"` 可得真实 PDF 直链（`https://assets.scriptslug.com/live/pdf/scripts/<slug>-2012.pdf?v=...`），**curl 直连可下真 PDF**（Skyfall 243KB，头部 `%PDF-1.6` 验证，PyMuPDF 提取 139 页 142KB 全文）——先试直链，`%PDF` 头验证成功即用；失败（HTML 头）再走页面 grep 直链/换源。dailyscript 对 2010s 片常 404（skyfall 实测 236B 404 页）。剧本引文注意：拍摄稿与成片可能有出入（对白措辞/场景细节），诚实声明标注「拍摄稿」。
6. **写卡片**：每条论断带 [S编号]；一手/二手明确标注；量化数据标口径；同一理念的多个出处并引。
7. **诚实声明**：未逐帧看片必须声明；抓不到的来源如实写「未取到」（域名失效、正文未渲染、反爬都算）；转述性引语（论坛/二手书评）注明非一手；简报错误写「勘误」条目。

## 来源技巧（本类任务验证过）
- **YouTube 视频简介页**（r.jina.ai 可抓）：播客/访谈视频的 description 常内嵌大段直接引语，等于免费一手摘录（Dolby Creator Talks 第 200 期简介含 Sonnenfeld 关于 Michael Mann「talk through emotions」的长引语）。抓 `https://www.youtube.com/watch?v=<id>` 后在简介段 grep。
- **公司官网 news 页**：cookie 同意条款占大半篇幅，正文在文件后部——从 `# <文章标题>` 行起 sed/截取。
- **Metrograph Journal 索引页含访谈全文节选（2026-08 李屏宾轮验证）**：`metrograph.com/<主题>/` 的 Journal 索引页常直接渲染整段访谈节选（侯孝贤 Positif 2001 英译全文节选就在 `metrograph.com/hou-hsiao-hsien/` 索引页里，含片比等量化数据）——抓索引页别只找文章链接，节选本身就可引用；具体对谈页 URL 用 `site:metrograph.com <人名> interview` 搜（Double Exposure 系列），直连 curl 可抓全文（一手）。
- **维基「无信息」≠「无人做」**：BR2049 维基全文无调色师署名、TFA 维基无 Company 3 信息——维基查不到就用 IMDb fullcredits 补，两者互为交叉验证。
- **IMDb 职员表抓取**：直连 curl 返回 0 字节、r.jina.ai 常被 Cloudflare 拦（2026-08 起不可靠）；可靠路径 = Wayback 快照 `https://web.archive.org/web/2020id_/https://www.imdb.com/title/<ttid>/fullcredits`（700KB+ 完整表）。grep 时注意角色行格式为「姓名行 + 角色行」相邻（用 -B2 -A2 看上下文），姓名 <a href> 与文字分两行，`grep -B4 <角色词>` 可能仍看不到姓名（中间隔 <td>...</td>），用 `grep -B10` 再筛 name。
- **对白级剧本镜像源（2026-08 后天轮验证，详见 references/tdat-session-2026-08.md）**：IMSDb 被 Cloudflare 拦（壳页 7.7KB 无正文，jina 同拦）时，`transcripts.simpleremix.com/script.php/<片名slug>-<年份>-<ID>` 直连可抓完整对白（180KB HTML → 48KB 纯文本）。但注意是**对白级来源**：无场景头/动作描述，成片某些场景镜像可能缺失（《后天》图书馆烧书戏无对白，只能靠原声带曲目名 Burning Books 佐证）——证据层级标注「对白级」并写入诚实声明。⚠️ **transcript 换行分割假阴性**：该站每行对白带 `\n`，整句匹配必失败（`We were wrong.\n\nI was wrong.`、`I will come for you. Do you understand me?\n\nI will come for you.`）——拆短片段验证或先压换行。同轮还验证：r.jina.ai 全线 Cloudflare 挑战页（5.8KB "Just a moment"，含 baike/ebert/indiewire/npr/guardian/imsdb）时，**直连 curl 成功率高**（Ebert 95KB/IndieWire 509KB/BBC 21KB/blackfilm 22KB/USA Today 32KB 全通）——与既有「先直连后 jina」顺序一致；百度百科走浏览器 innerText 提取（词条 ID 不确定先 web_search "片名 百度百科 item"）。
- **小播客站点域名易死**：Art of the Grade 等站点常已停用，如实标「未取到」，不要硬编内容。
- **Fandom（Wookieepedia 等）正文常不渲染**：r.jina.ai 只回导航时，标「未取到正文」，换 IMDb/官网补。
- **JS 渲染型官网正文在 script/JSON 里，bs4 提取会"提取出空气"（2026-08 Letteri 轮验证）**：Next.js/React 营销站（典型：维塔官网 wetafx.co.nz 的影片页/文章页）正文不在可见 HTML 中，按「decompose script 后再 get_text」的常规提取只剩几百字节（awardsdaily 229B、wetafx 官方页 158B），但**关键短语 grep 原始 HTML 仍有大量命中**——正文以字符串形式内嵌在 script 标签里。对策三步：①提取失败先探测——`re.finditer` 关键短语（如 "performance capture"）在原始 HTML 的命中数，>0 即内容在、提取器该换；②**关键词窗口法**读正文——写 `win(fname, key, before, after)` 函数打印关键词前后各 500-1500 字符的 strip_tags 窗口（剥 script/style/标签/压空白），按主题逐窗口阅读，比整页转换可靠；③最终 grep 验证直接对原始 HTML 跑（引语字符串一般不被标签切开，无需完美正文提取）。⚠️ 此类官方站反而是金矿：wetafx.co.nz/films/filmography/<片名> 的官方文案（"Kong is a CG title character who delivers a very complex performance without the aide of dialogue"）是准一手来源，别因提取失败就放弃。
- **华语影人必须抓中文深度资料**：澎湃/新浪/Mtime/时光网等常含一手引语（新浪 2003《2046》发布会报道直接引杜可风中文原话，与英文访谈互为印证）；中文维基的奖项清单比英文维基更细（获奖影片逐年列出），两类都要取。
- **维基主条目的「参考文献」段是金矿（2026-08 Storaro 轮验证）**：refs 列表常直接给出一手来源链接——ASC/AC 自撰文章、Guardian 专访、行业杂志存档。写卡片前先扫一遍人物条目的 refs 段，往往比搜索引擎更快挖到本人亲撰长文（Storaro 轮由此挖出 ASC 2017 亲撰色彩理论长文与 Guardian 2003 逐片专访）。
- **DP/摄影指导的 ASC 一手文章模式**：theasc.com / ascmag.com 的 flashback 系列（AC 旧刊原文重发，常为本人圆桌访谈全文，如《Apocalypse Now: A Clash of Cultures》2001 年 2 月刊）与「本人自撰」长文（如 Storaro《Who's Afraid of Red, Green and Blue?》2017）是欧洲老牌 DP 的顶级一手来源；检索式：`site:theasc.com OR site:ascmag.com flashback <人名/片名>`；ASC 主席专栏（President's Desk）常整段转引大师原话（Plato's Cave 篇含《末代皇帝》光与影长段原文）。
- **r.jina.ai 无法代理 web.archive.org**（403 AbuseAlleviationError，封锁至 2035 年的长期禁令）：需要取 Wayback 存档内容时直接 curl 原始 archive.org URL 或换源，不要反复重试 r.jina.ai；「未取到」就如实写进诚实声明（Storaro 轮 ICG 2004 访谈即因此未取到）。⚠️ **Wayback 上的 PDF 存档直连可下（2026-08 穆伦轮）**：jina 403 后 `curl -sL -A "Mozilla/5.0..."
