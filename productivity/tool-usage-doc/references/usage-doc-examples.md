# 使用说明书示例参考

> 本文件收录 1 份已交付的"用法说明书"作为示范——下次写同类文档时不必从头发明结构。**示例不止于结构,还有:哪里被用户当场拍板的版(值得复用)、哪一版被否(避免复用)**。

## 示例 1:MemOS 使用说明书(NAS 192.168.1.2:8001)

**文件**:`Documents/Hermes/分析/MemOS使用说明书-2026-08-26.md`

### v1 被否(概念全表型)vs v2 通过(场景驱动型)的对比

| 维度 | v1 被否 | v2 通过 | 关键差异 |
| --- | --- | --- | --- |
| 主体章节 | 1. 是什么 2. 部署 3. 核心抽象 4. 工具 5. 端点 6. 写入 7. 检索 8. 多cube 9. 进阶 | 1. 30秒入门 2. 用 vs 不用 3. 写入 4. 检索 5. 管理 6. 多cube 7. chat 8. 失败诊疗 9. 原理 | v2 把"是什么"砍到只剩一句话,主体章节按"动词"分(写/搜/管理/...) |
| 端点出现方式 | 30 个全列,带 method+path+summary | 只列 6 个核心(写入/搜索/管理/...),其余归附录速查 | v2 不让端点表抢注意力带宽 |
| 命令占比 | 估算 <30% | 估算 >70% | v2 让代码块成主体 |
| 字段表 | 字段+类型+语义解释 | 字段+实战值(默认+推荐) | v2 给"实战怎么填",不是 API doc 复制 |
| 失败诊疗 | 无 | 6 个真实现象+查→修流程 | v2 收进实战踩坑表 |
| 用户原话反馈 | "我需要实际地详细地用法" | (通过) | v2 是对这句反馈的直接回应 |

### v2 可复用的固定模式

1. **30 秒入门 = 写入 + 搜索 + 内置工具**,三块并排(用户能挑一个就跑通)
2. **"用 vs 不用"双表**——上方"该用",下方"不该用"+"用什么替代"
3. **场景主体每节模板**:一句话判定 → 1 个完整命令 → 1 个判断法 → 1 个注意事项
4. **判断法独立一节**——如"三步过滤"判断该不该写,从场景主体中抽出来显眼
5. **失败诊疗 = 现象/先查/再查 三列表**——只收实战踩坑,不收"理论可能"
6. **附录 C 永远写**:`openapi.json` / 官方文档 = 活契约,说明书会过期,但"判断标准"价值不减
7. **元信息开头第一行**:`基于 vX 实测,适用 X`——告诉用户"这份文档保质期"

### 这次没做但下次该做的

- 端到端验证(add → 等 30 秒 → search → feedback → delete)截图存档 = 给个"物证",不只是文字说明
- Python 一键封装进 `~/scripts/`,作为本机沉淀的工具(本次没做,因为用户没要求)
